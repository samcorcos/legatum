# The walls browser tests need a one-human save, and a walled city's card is two rows taller (2026-11-25)

`wallsFixture()` seats three humans. Since Continue sends a save with more than one human seat to the multiplayer screen ("Host this save"), `e2e/walls.spec.ts` never reached the game and all six cases timed out on `turn-number`. The spec now marks every seat after the first as AI, in both `fixture.players` and `fixture.setup.players`, as the city and Guide specs do; a browser spec that loads a save through Continue needs exactly one human seat.

Two things behind that were also stale after Breakable Walls (#212). The forecast odds row is absent when neither side can be destroyed in one attack (`OddsRow` returns nothing at 0% and 0%), which is now the case for a Spearman against a walled city, so the "risk row sits above the odds" check compares against the strength tables instead. And the defender's Walls bar adds two rows to the sides, which pushed the walled-city card 32px past its 526px box at 1000x600; under 760px tall, a card with a Walls bar now drops the Walls sentence that repeats the bar and the strike breakdown, the same lines the whole-fight card already drops.

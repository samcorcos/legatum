## 2026-11-22: Team map pings travel over the host's message channel, not as an order (`claude/review-team-pings`)

- **Why not an `Order`:** an order is stored in the state and tapes and would bump `RULES_VERSION`. A ping is team talk: it changes nothing in the game. Online, the game runs in the host's tab and the relay only tunnels frames, so the host protocol (`crates/wasm/src/host/protocol.rs`) is the channel: `ClientMessage::MapPing{hex}` in, `ServerMessage::MapPing{from, hex, turn}` out to the sender's teammates only. Hot seat never leaves the store (`app/src/teamPing.ts`). `RULES_VERSION` stays at 52.
- **Capability gating without errors:** the host's `welcome` carries `map_pings: true` (omitted when false). The client sends a ping only after seeing it and hides the control otherwise, so a newer client on an older host never sends an unknown message (the host would answer it with an error toast). An older client receiving a `map_ping` frame ignores it (the message switch has no default).
- **Never fill the reliable queue:** pings use a separate bounded slot per connection (`outbox.rs`, the latest 8), because a slow reader that overflows the 16-delivery queue is closed. The host limits a seat to 24 pings per planning turn and drops the rest without an error; the client adds a 600 ms gap. Pings off the map are an error, from a connection with no seat too.
- **UI:** a quiet strip at the foot of the right sidebar (not under the minimap: the minimap is hidden at 1000x600 once a unit is selected), P as the shortcut, Esc cancels, and "Ping this tile" in the touch tile card. The ring is drawn like the report arrow: its own live flag in the map loop, so a map with no ping does no extra work; the ring pulses for 2.4 s the first time a viewer sees it, then stays still until the turn ends (still at once with Map animations Off or reduced motion).
- **Gotcha:** `frameChanged` compares each frame key with `Object.is`, so the pings handed to the map must be a memoized array, or the map redraws every render.

# Team ping chime; the guest rate cap already lives in the relay (2026-11-25)

- **A teammate's ping now chimes** (`feel.teamPing`, `multiplayer/team-ping.m4a`); your own ping stays silent, since you just clicked it. The source is Bastianhallo's CC0 "Level up" chime (Freesound 682633), fetched from Unciv's mirror on raw.githubusercontent.com because kenney.nl, Freesound and OpenGameArt are blocked from cloud sessions. `tools/audio/build_audio.py` entries now take an optional fifth field, a clip length in seconds (kept from the start, faded out over its second half), so the 4 s chime run builds as a 0.6 s ping. The cloud has no `aac_at`, so this file was encoded with ffmpeg's `aac`; a rebuild on the Mac re-encodes it with the rest.
- **"Host per-connection message rate limit" from the Fable review needed no new code.** Every guest socket already has its own token bucket in the relay (`GUEST_RATE` in `infra/relay/src/shared.ts`: burst 300, 5 messages a second, 128 KiB a second), and a socket over it is closed with 4029 before its messages reach the browser host. The host's own caps (`MAX_PINGS_PER_TURN`, `MAX_STAGED_ORDERS`, five wrong join codes) sit behind it. A second bucket in the browser host would only matter for a relay we do not run.
- **The Royal Tomb's map landmark is still owed.** A landmark and its three construction stages are paintings made with Codex image generation on the Mac (`tools/art/wonder-art.py`), which a cloud session cannot run. The tomb's goal cards already wear its gilt goal mark (`goal-royal-tomb`), so the celebration side is covered.

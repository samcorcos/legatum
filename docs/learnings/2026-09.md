## 2026-09-29: Playtest-3 follow-ups (G15 Return closes overlays, G16 cost chips, G17 decision cards close, G19 A/D keys)

- **One overlay stack, in the capture phase.** The turn report was made non-modal on purpose (keys kept working), so Return with the report open went to the next decision: with an offer pending it swapped the report for the inbox, and the map never showed. `handleOverlayKey` (gameplayKeys.ts) now owns Return and Escape for every surface marked `data-dismissible` (guide, research, diplomacy, victory, report, topmost first) and bails when a decision modal (any `dialog[open]` or `[data-game-overlay]` without the mark) is up. It must run on window in the capture phase, because the guide, research and inbox stop key propagation. That also puts it ahead of Tip's Escape (document capture) and of MomentLane's (window capture, registered later), so Escape defers explicitly to `tipOpen()` and a showing `.moment-card`. A mounted-but-closed `<dialog>` still matches `[data-dismissible]`: query `dialog[open]` separately.
- **Return belongs to a control only when the player Tabbed to it.** `:focus-visible` can't decide it (programmatic focus on open inherits the last modality, and a key press can flip it). A flag set by Tab and cleared by pointerdown does: a keyboard user's Tab to Accept then Return still accepts, a mouse user's Return closes.
- **A chip inside a button changes its text, not its name.** Cost chips and key chips live inside the buttons, so every such button has `aria-label` equal to its label and `aria-describedby` on the chip's screen-reader sentence. Tests that matched `textContent === 'Declare War'` pass vacuously after such a change (a negative `some(...)` check stays false); match the accessible name.
- **Show a spend's after-state against the pool it is paid from.** The first Buy chip used "Gold left after all queued buys" + price, which was wrong when the buy itself is invalid (not subtracted): `purchasePreviews` now returns each option's `gold` (the treasury before that purchase). Influence uses `influenceSpend()`, the same projection as the offer card's sentence (income, then border claims, then other queued costs): the chip shows `pool → pool − cost` when affordable either way, otherwise the projected end state, flagged "debt". A proposal pays on activation turns later, so its chip has no after-state. Trust can be negative and is never "debt".
- **The contrast audit measured screen-reader-only text** (1 px clipped spans have wide text rects) and failed at 1:1. `e2e/contrast.ts` now skips runs whose own box is at most 1 px; the gallery has chip-only buttons so the chip ink is still audited in both looks.
- **WebKit (Tauri on macOS) ignores `::marker { content }`**, so the red − / green + "For you" marks are real elements, not list markers.
- **Screenshots:** `scrollIntoViewIfNeeded` on a phone-sheet row sometimes scrolled the overflow-hidden game root by hundreds of pixels (a blank half screen that isn't a layout bug). Scroll the element into view, then reset `scrollTop` on the root ancestors, and park the mouse where no tooltip opens.

## 2026-09-29: Playtest-3 benchmark: the human out-expanded both the Hard AI and the Proxy
- **The same map is effectively one game.** Re-seeding every scripted brain's tie-break jitter (16 salts) left seat 0 identical through turn 136, and outcomes diverged only after about turn 150. To get a spread, measure across maps, not across brain seeds.
- **The human was far ahead of both bots in its own seat.** On the playtest-3 map a Hard AI in that seat had 3 cities and 2 VP at turn 136, against the human's 8 cities and 7 VP. It won 0 of 16 games. Proxy v4 won 16 of 16, but only at turns 229–238 and after founding just 3 cities.
- **The master gap is unchanged.** On 200 rotated Standard maps with barbarians on, Proxy v4 still beats 7 Hard AIs 63.0% of the time, the same as around playtest 2. G8's pacing levers only shorten games: 60.5%, with the median win moving from turn 211 to 190.
- **The largest macro gaps are expansion after the second city and Settler escorts.** The Hard AI's third city comes at turn 135 against the human's 65, and its Settlers spend 35 turns per game outside its borders with a military unit on the same tile only 7% of the time; the human's did 40%.
- **Coalitions form but don't fight.** All 26 AI alliances in the playtest named the human as the coalition target, but only 2 AIs declared war.
- **`legatum-sim` Proxy runs default to barbarians off.** Pass `--barbarians true` for current-rules numbers.
- Details: `~/LegatumData/analysis/playtest3/benchmark.md` and `crates/sim/examples/playtest_bench.rs` (replay a save and report macro metrics, play the save's map with any brain in seat 0, or run rotated maps).

## 2026-09-29: Playtest-3 AI post-mortem: barbarians still change builds, and the coalition never fights

- Replaying `playtest3-final-1849` with a fresh Hard `ScriptedBrain` on each seat's view reproduced all 945 taped AI turns exactly, so a playtest tape is a complete, re-runnable record of AI reasoning. `crates/sim/examples/playtest_ai_trace.rs` dumps per-turn state/events and checks this; test-only probes inside `production` and `diplomacy` print option values and war-declaration inputs at dumped turns.
- G10's "barbarians never change what a city builds" only covers `item_base_value`. `plan_emergency_production` still uses `ctx.threat` (barbarians included): 9 civilian builds were converted, including 291 Settler Production (Germany's first Settler at 147/190 at T50; it stayed at 1 city all game).
- `choose_item`'s time discount (`value × 60 / (turns + 60)` at Standard) makes a 50–64-turn Settler lose to a Workshop with lower value (Germany T81: 912 vs 1037). At the 3-Production floor the Settler rarely wins again.
- Hard leader pressure never arms an AI at Peace: `desired_army` only adds it with a reachable *enemy* (at-war) city. AIs willing to declare on the leader could not see it (scouts dead and never rebuilt), and the one that could reach it had aggression 25: two coalition wars, 0 battles.
- The AI Switzerland never built a Market in 136 turns; the human Switzerland built four. AI gross gold stayed at 1–5 per turn, below every 2×-cost purchase price, so "unspent gold" in these games is poverty, not hoarding.

## 2026-09-29: Playtest-3 release check fixes

- **A flex row of totals needs the totals rigid and one designated shrinker.** `.stockpiles { min-width: 0 }` let the Iron and Coal chips shrink under their content, so "Coal 30 (0)" drew over "Pop." and the research text ran into TURN at 1440, 1280 and 1024. Totals are now `flex: none` and only the research cell (`flex: 1 1 0; overflow: hidden`) shrinks. Media queries could not keep the research text readable, because the bar's content varies (0 to 2 stockpiles, the treasury warning, a one- or two-line plan): at 1440 the worst case was 21 px too wide while the common case fitted. `TopBar` measures instead: after each render it applies compaction steps (`TOP_BAR_COMPACTION`: stockpile names, the warning's detail, cell padding, incomes, the wordmark, the Research label, the Technologies button) until `.tb-stats` stops overflowing and the research text is whole, and only then truncates. The header's size never depends on the steps, so the ResizeObserver cannot loop. Phones got two separate fixes: two stockpiles share one 44 px cell (two 44 px chips stacked were 90 px in a 52 px bar), and the treasury warning moved into the Gold cell (as a grid item it pushed Research onto a second row). `e2e/topbar.spec.ts` checks both boxes and visible text for overlap at 1440, 1280, 1024 and 390 in both looks.
- **Chromium reports `net::ERR_ABORTED` for a 204 response whose body is never read**, after the fetch has already resolved (the archive POST). A release check that counts `requestfailed` events should match each one against the response status and filter 204 + `ERR_ABORTED`, or every turn looks like a failed request.
- **Core resolves Influence in a fixed order: income, then border claims (phase 10), then the diplomacy boundary** (breach fines, pact eligibility, signing costs). A forecast that compares the signing cost with the current pool is wrong whenever a border tile becomes affordable that turn: the Pact card said "go 1 into debt" and the pool went to −10. `boundaryInfluence` (influence.ts) is the first step of the same projection that gives border forecasts.
- **Found City stays validated at resolution only.** `validate_orders` sees the true state, so rejecting there would reveal hidden cities and borders, and a check against the player's view could reject an order that resolution would accept (a capture earlier in the same turn changes the tile's owner). The UI disables the button from the player's own knowledge (`foundCityBlocker`), and the report explains a Settler whose destination stopped being a legal site, since core keeps the move going.
- **A label and its click must come from the same decision.** The phone's "Next: Unit" label came from the CTA's decision while the click asked `nextDecision()` for whatever follows the selection, so with the last unit selected it opened Research. Next now calls the CTA's own action.

## 2026-09-29: UI clarity pass 2: names, places and screenshots across a merge

- **Core writes player names into its own text.** Even after every UI surface used `empireNameOf`, report lines still said "blocked by AI 3's Scout": MoveBlocked reasons are formatted in Rust with the raw player name. The report context now has `renamePlayers(text)` (your / "Switzerland'"), applied to core reasons. When changing how the UI names something, grep the event reasons core formats too.
- **A tooltip on a legend under a bottom-anchored panel pops by itself.** The lens panel grows upward when a lens with a longer legend is chosen, which slides the legend under a cursor that never moved; Chromium fires the hover and the tip covered the key. Place such tips beside the panel (`placement="right"`), not over it.
- **Anything drawn under unit tokens must avoid the token footprint.** The barbarian camp was drawn under units, so a guard hid its pennant completely. A guarded camp now stands left of the token with its pennant mirrored to fly left; an empty camp fills the tile. Check canvas marks with and without a unit on the tile, in both looks: the red dashed outline read on Atlas paper but not on Court's dark terrain until it got a light halo.
- **Hover cards and city banners.** `placeCard` already avoided DOM panels; banners are canvas, so `draw` now returns their rects (`bannerRects`) for the card anchor's avoid list.
- **Like-for-like screenshots across a rules-changing merge.** After merging G10, the pre-merge save no longer loads in the new engine. Keep a copy of the pre-merge `app/src/wasm-pkg`, and serve a `git archive HEAD app` snapshot with that old package (plus a cloned `node_modules`) on another Vite port: the after shots then use the exact save and states of the before shots. New-engine features (barbarians) get their own before/after pair from a post-merge save, with the merge commit as "before".

## 2026-09-28: UI clarity pass (G13): patterns that worked

Audit: `docs/ui-audit-2026-09-28.md`.

- **Name the target.** A primary button that names where it leads ("Respond to the offer", "Give the Soldier orders") beats a generic one ("Go to first decision"). "Keep planning" is the dialog's ✕ and Esc, not a third button: three equal buttons wrapped to two rows and had no visual hierarchy.
- **Rules go behind the action.** Hints and panels had become rule dumps: the capital hint listed Fortify, Sleep, Wake and Heal, and the Scout panel floated an italic rules paragraph over the map. One action sentence in view, rules in the tooltip or in the guide chapter the hint already links to. Every fact stays reachable; nothing is deleted.
- **One primary per screen counts across panels.** On phones the sheet's unit action and the turn row's Next were both filled primaries. Each component was correct on its own and wrong together. Decide the primary from the whole screen: while one of our units or cities is selected, the turn row steps back.
- **The default-focused button must be the visual primary, and it must be safe.** Game over focused "View the map" (showing a focus ring) while "Back to title" was filled, so both looked primary. Now the focused, safe choice is filled, and Return can never leave the game.
- **Destructive actions don't belong beside navigation.** The top bar's research "Clear" was styled like Victory and Technologies, and it also caused the research chip to clip at 1024. The panel's "Clear queue" is enough.
- **Stacking bugs only show when the menu is actually open at phone size.** The game menu was painted under the phone's VP strip and bottom sheet (all at the HUD's z-index), so Save and Exit were unreachable. A `.topbar:has(.menu-pop)` z-index raise fixed it without touching the other overlays.
- **Copy must follow the rules.** A hint said every other team is at war with you, after diplomacy made Peace the default. Hint copy that states a relation now reads it from the view (`hintCopy`).
- **One naming function for anything that names an empire in text.** "Switzerland (Swiss envoy)" came from gluing faction and player name together in three places (`empireTitle`, `empireLabel`, `format.ts`). `empireNameOf` now decides once: faction first, and the player name only when it adds information (not a seat default, doesn't restate the faction, or two teams share the faction). Surfaces that still print a raw player name (the victory race rows, unit possessives) are listed in the audit.
- **Map labels that share a hex need one geometry source.** The settle badge had its own "0.8 r above centre" and the resource medallion its own "top of hex", so they collided. `medallionTop(hexPx, city, stacked)` now tells the badge where the medallion ends. Likewise, the stack lift is a shared `STACK_LIFT` constant, not two 0.3 literals. When a case can't be found in a real save (a resource under Best spot, a stack on a resource), stage it by editing the local view in the browser: render only, no orders.
- **Tooling.** A save made by one core build may not load after a core change (G9 added unit XP), so keep a "before" save and server from the old commit: a `git archive` snapshot plus a symlinked `node_modules` on a second Vite port. After `scripts/build-wasm.sh`, the running dev server reloads, and screenshots taken during that reload time out, so re-run them.

## 2026-09-28: The minimap (playtest 3, G5)

- There was no free bottom-right corner. On wide desktops (> 1280 px, mouse) the unit command bar owns the whole bottom centre (384 px to width − 352 px) and the turn dock owns the corner, so the minimap takes the corner and the turn dock stacks directly above it (Civ 6 puts Next Turn over the minimap). At 1280 px and below, and on every touch tablet, the unit panel docks in the left column and the bottom row is free, so the minimap sits beside the turn dock. Phones get a 44 px Map button between the race strip and the lens toggle, opening a modal overview (`data-game-overlay`, so gameplay keys pause while it's open).
- The first cut clipped the player's own race row at 1440×900 (pillar 4) while leaving a ~50 px dead gap above the turn dock: the race had a fixed cap (`100% − 72px − 352px`) and the dock was capped by the race's bottom, so neither used the other's slack. Two fixed reserves can't share a column. Now the dock takes what it needs (capped only so the race keeps `--race-min`), VpTrack publishes the dock's measured `--dock-height`, and the race gets exactly the rest: one-directional, so no resize loop (a mutual race-bottom ↔ dock-height dependency drifts a few px per frame). The race's own row is `position: sticky; top: 0; bottom: 0` inside `.vp-rows`, so it stays in view whenever the rows must scroll (1024×768 touch rows are 62 px: eight can't fit). Off phones the Developed Empire line moved into your own row's breakdown, and the ≤ 860 px compact race rules now apply up to 960 px, which fits all eight rows at 1440×900 and 1280×800 in both looks, and at 1366×1024.
- A panel that hugs a fixed-aspect canvas should size from the canvas: fit the map into a max width and height, then let the panel shrink-wrap it. The first cut gave the panel the column's width and centred the map, which left dead margins.
- The main camera lived in a MapCanvas ref. `map/camera.ts` now exposes it: MapCanvas registers a host and calls `notifyMapCamera()` from its draw loop only when x, y, zoom or the canvas size changed, so the minimap redraws its frame on pans and zooms without polling or per-frame work. `centerOn(hex)` / `centerOnWorld(x, y)` snap; the store's `jumpTo(hex)` is still the eased focus pan.
- The map does not wrap horizontally: `tileIndex` returns −1 off the offset grid and `clampCamera` clamps x, so the minimap is a plain rectangle.
- On macOS's case-insensitive filesystem `Minimap.tsx` and `minimap.ts` in one folder are the same module to TypeScript (TS1261, and the import resolved to the wrong file). The pure half is `minimapView.ts`.
- `auditOverlaySlots` treats the map canvas as a slot, which is right on phones (the canvas is a reserved region) but on desktop and tablet the full-screen canvas intersects every HUD panel. `e2e/minimap.spec.ts` drops the canvas layers before asserting no overlaps.
- A Vite dev server started in an agent worktree whose `app/node_modules` is a symlink to the main checkout answers 403 for font files (they resolve outside Vite's allowed root), so screenshots silently use fallback fonts, and `e2e/lenses.spec.ts` (which runs its own Vite server and fails on any console error) fails all six cases. Clone instead of linking: `cp -cR <main>/app/node_modules app/node_modules` is an instant APFS copy-on-write clone. `e2e/staging.spec.ts` also needs `target/debug/legatum-server`, not just the release build.
- `src/mock/mockClient.test.ts` "keeps view() fast" failed in a full `vitest run` at load average 191 (other agents running) and passed alone. It is a wall-clock test; rerun it before treating it as a regression.

## 2026-09-29: Barbarians (G10): a reserved owner, and the cost shows up in AI expansion, not survival

- Barbarian units are ordinary units owned by a reserved `PlayerId::BARBARIAN` (u8::MAX) on `TeamId::BARBARIAN`, outside `GameState::players`. `GameState::player` returns a shared read-only record for it (neutral Japan unit stats); `player_mut` has none. Movement, combat, capture, sight and fog handle them unchanged, and they can never get Gold, VP, a brain or a diplomacy row. The crashes this approach exposed were all direct `players[owner.0 as usize]` indexing, in core `reset_turn`, AI `purchase_defense`/`military` and the TS mock. Always go through `player()`/`team_of()` (TS mock: `playerOf`/`teamOf`) for a unit's owner.
- Anything that holds per-team or per-owner state has to accept an owner outside `players`: threat memory (`threat_observations`), `PlayerView::team_of`/`faction_of`, the fuzz occupancy oracle, and the UI's `atWar`.
- Sims: a barbarian-free AI would have looked fine on eliminations (0.04 per game) and game length (unchanged). The real cost was 5 to 7% of empires never founding a second city. Traces showed three causes: a captured first Settler (the AI then waits for Workshop and Granary before retrying), defenders interrupting a Settler build in a 3-Production capital, and Settlers waiting on remembered danger. Two things helped: camps 6 from cities instead of Civ 6's 4, and not letting barbarian threat change city builds, since they never assault cities. It is still 3 to 5% versus 0 to 1% without barbarians. Always measure "never reached a second city" when adding any neutral threat.
- Staging settings are acknowledged by comparing JSON strings, so a new optional room field must either be sent by both sides or be compared normalized (`settingsAcknowledged`). Four LAN specs caught this after the server began echoing `barbarians: true`.
- Game-setup flags that default On for new games but Off for old saves: `serde(default)` plus `skip_serializing_if` false keeps Off setups byte-identical, so old tapes still hash. The new state (`GameState.barbarians`) is an `Option`, and saves carrying it are `save_version` 5, so older builds refuse them instead of silently dropping the camps.
## 2026-09-29: Map resources, increment 1 (G11 "Iron on the map")

- A guaranteed deposit isn't a usable one. With every start's Iron placed 3–5 hexes out, 23% of AI empires never owned an Iron source (24 Quick games, median first source turn 62): border growth ranks tiles by yield, so a ring-3 Hills tile was never picked, and rivals' second cities claimed deposits that faced them. Two changes fixed it (4.7% never, median turn 38 over 240 games): borders pull toward known unclaimed Iron/Coal (+3 on the deposit, +2 next to it; `resources::border_pull`, shared by both border paths and mirrored in the mock), and the guaranteed Iron prefers the ring-3 tile farthest from other starts. Test a placement guarantee by whether empires end up *owning* it, not by whether mapgen placed it.
- Start fairness survives resources only if every start gains the same quality. Guaranteed start bonuses are flat-land Food/Production types (+6 quality each start); strategic deposits are hidden at the start, so `site_quality` ignores them; other deposits keep out of radius 3 of every start. `placement::validate_rivals` rechecks the spread with resources.
- Pay-on-start with refunds needs one reconciliation hook, not per-path bookkeeping: `resources::switched(state, city, previous)` runs wherever `producing` changes (orders, queue advance, deferral, invalidation, bought buildings), and completion calls `release(.., false)`. Payments live on `Player.resource_paid`, so a captured city's paid build is simply dropped; the stale entry is ignored because it no longer matches the city's previous build. The cap limits income only, so a refund is never lost.
- A resource shortage is a *temporary* queue blocker (skip and keep, like a missing spawn tile), not a `production_blocker`: otherwise `can_produce` fails and players can't even queue a Trooper behind other work while the Iron accrues. SetProduction and the head of SetProductionQueue check it; later queue items pay when they start.
- Every AI brain goes through `Brain::orders`, now a provided method that hides resource-blocked options and drops orders beyond the stockpile (`crates/ai/src/stockpile.rs`); brains implement `plan`. Two cities starting Troopers on the last 10 Iron would otherwise fail validation, and several full-game tests assert every AI order validates.
- The settle advice (`app/src/map/settleAdvice.ts`) recognises breakdown lines by label prefix, so core's "Known radius 2:" label must keep that prefix when it changes.
- City banners are several hexes wide, so anything drawn at the top of a hex (resource medallions) is hidden on the city's tile and its same-row neighbours. `bannerRect()` (sprites.ts) gives the rect before drawing, and a covered medallion moves beside the unit token instead.
- The mock's turn resolution pre-validates unit orders, which would report a same-turn Iron shortage in validation wording; the mock leaves the Iron check to apply time so its OrderFailed text matches core.
- Playwright can edit a WASM save losslessly: quote integers of 16+ digits before `JSON.parse`, edit, drop `archive`, stringify and unquote, then `loadSave`. That builds a mid-game scenario (a city owning Iron, a known tech, a stockpile) without a Rust fixture. Screenshots taken right after `loadSave` catch the fading loading plate; wait for `.loading-screen` to be gone.
- Balance (240 games per speed, same seeds, master `6882b24` vs G11): best/worst faction win rate 3.46x → 3.50x at Quick and 2.53x → 3.19x at Standard; both were already far over pillar 8's 1.5x. Sparta is unchanged (~5–7%); Byzantium drops ~1.5 points at both speeds (within noise). See docs/sim-results/2026-09-29-g11-resources-increment-1.md.

## 2026-09-28: Civ-style yield icons (playtest G6)

- The yields lens drew a parchment chip with icon + digit per yield on every tile, plus a blue wash over the whole map; the player called it "way too busy". Now `app/src/map/yieldIcons.ts` draws each yield as its icon repeated per point (Civ stacks: 1, 2 side by side, 3 as a triangle, 4 as a square, 5+ one icon and a numeral), no chip, no wash, under units and banners. Icons at hex radius ≥ 18 px (zoom ≥ 0.5), one dot per type down to 11 px, nothing below (zoom < 0.31).

## 2026-09-26: The painterly map in the real canvas renderer

- Everything that only changes on turn resolution (terrain, coast, relief, glyphs, towns, fog, territory, unexplored veil) is baked into 512 px chunks per zoom level (`app/src/map/terrain.ts`), about sqrt(2) apart in device-pixel scale. A frame is ~10–25 `drawImage` calls: 0.2–0.9 ms per frame and a steady 60 fps panning and zooming on a 60x40 map at 2x DPR (headless Chromium). A new turn diffs a per-tile signature and marks only nearby chunks stale; stale chunks keep showing until re-rendered within a 7 ms/frame budget, so turns never flash. Field rebuild per turn: ~25 ms.
- Coastline without per-chunk blurs: keep the land field as a JS float grid (4 world px), gaussian-blurred once per turn. For a straight coast the blurred field is Phi(d / sigma), so `sigma * probit(field)` is the signed distance to the coast. That gives crisp, anti-aliased coast and wave-ring lines at any zoom from one bilinear sample per pixel, and a summed-area table of "near coast" cells lets 16x16 blocks of pure land or sea skip the per-pixel work.
- Blurs inside a chunk fade at the chunk edge (the canvas filter treats outside as transparent), which shows as seams. Blur on a padded scratch canvas (72 px) and copy the middle.
- A look (Atlas light, Court dark) is one token block in `app/src/brand/tokens.css` under `:root[data-look]`. Even the panel frames are tokens: `--frame-image` is a 9-slice SVG data URI used as `border-image ... fill`, so the ink double rule and the notched deco corners (which a plain `border` + `clip-path` can't draw, since clipping removes the border along the notch) swap with the palette. `border-image-width` larger than `border-width` paints into the padding, which keeps content offsets identical across looks.
- Canvas text does not trigger `@font-face` loading; call `document.fonts.load()` for the faces the map uses and rebuild cached text sprites on `loadingdone`.

## 2026-09-26: Cross-target replay coverage

- A matching final save hash does not verify continued play after loading. Both native and WASM tape checks now replay continuously and from a save/load at every turn boundary, including the initial and final states. Full saved-state equality and the recorded per-turn hashes are checked.

## 2026-09-26: Tauri desktop app

## 2026-09-26: Determinism and WASM

- Never cast a `u64` seed or hash to `usize` in game logic: `usize` is 32-bit on wasm32, so `seed as usize` truncates there and native and WASM diverge (found in `GameSetup::standard`/`all_ai` faction assignment, which also overflowed in debug for large seeds). Reduce in `u64` first, e.g. `(seed % 3) as usize`.
- On wasm32-unknown-unknown, `catch_unwind` compiles but catches nothing: a Rust panic surfaces in JS as `RuntimeError: unreachable`, with the real message only in the panic hook's `console.error`. The UI must recover by rebuilding the `Game` from its last save.
- Save JSON contains `u64` bitset words as plain JSON numbers. JavaScript must treat the save string as opaque (never `JSON.parse` and re-serialize it) or precision is lost.
- `wasm-pack build --out-dir` is relative to the crate directory, not the current directory.
- Integer rounding: apply percentages to the result, not the delta (`total * 75 / 100`, not `total - total * 25 / 100`), or small values escape the modifier entirely. Found by the Astra core review in the Japan penalty and tech diffusion.

In tools/league coach mode, a research review is due when `review_seconds` has elapsed OR `gen % review_every == 0`. `--coach-every 1` therefore reviews every generation and burns the whole research budget (6 sonnet calls) in six consecutive generations. Leave `review_every` null and let `review_seconds` (default 7200) set the cadence. Also, the coach A/B's default 128 held-out games (16 maps) is too few to confirm effects around +0.03; use 256 or more.

## 2026-09-30 — Mock ranged Battle events must report HP after the whole ranged phase
The TS mock applied ranged damage shot by shot and put the running HP in each Battle event, while core (`battle::apply_stage`) sums the whole ranged phase's damage first and reports HP after all of it. Parity tests never had two shots on one target, so nobody noticed. City strike makes that common (a Ranger and a city, or two cities, hitting one unit), so the mock now applies unit shots and city shots together, then emits every event, then removes the dead in unit-id order, like core. Any new simultaneous stage in the mock should follow the same order: plan from the snapshot, apply everything, then emit.

## 2026-09-30 — Hard v2 (league openings in the game): equal to old Hard head-to-head, longer games, and all-one-opening tables can stall
Hard seats now draw a league-tuned opening (crates/ai/src/hard_v2.rs; genomes in the generated tuned_openings.rs, refreshed by tools/league/export_tuned.py). Checks worth reusing:
- Prove the wiring before trusting a validation: the same seats and genomes on the league's frozen binary and on the game build played six Standard games identically (turns and winners), so the integration adds no behavioural change of its own.
- A single `enabled()` flag that means both "league run" and "any seat option" silently turned the one Hard v2 seat of a rotation run back into old Hard (0 v2 seats reported). Keep "which seats are special" separate from "the runner builds brains itself", and have the report name each seat's brain (`hard-v2:<Opening>`) so a zero is visible.
- On 104 Standard games with one Hard v2 seat against seven old Hard seats (seat rotated), Hard v2 won 12.5% (95% CI 7.5–20%), exactly parity: the league's gains are relative to other openings, not a strength jump over the old Hard. Against the Proxy benchmark (128 Standard games, rotated) the Proxy won 9 with seven Hard v2 opponents and 3 with seven old Hard (not significant, but not the direction we want). Measure an AI swap against both the old AI and an outside benchmark before calling it stronger.
- All-Hard-v2 tables (100 Standard games) ran 333 turns on average against 269 for old Hard on the same seeds (Standard's nominal length is 225), with 1 stall: a table where all eight seats drew DefendedExpand (69% weight, so about 5% of games) ran to the 1,200-turn cap. The equilibrium weight of one opening sets how often a whole table mirrors it; watch the floor and the dominant weight, not only the per-opening win rates.
- The opening phase machine flaps: an army at the edge of `defend_distance` flipped Opening/Defend (and the production strategy) every turn, up to 57 switches per seat.
- Rule changes that fire automatically (city strike) break hand-built scenario tests far from the rule's own code (AI retreat math, analysis reproductions, playtest replays). Scenarios recorded under the old rules pin the old rule explicitly (`no_city_strike`) rather than having their expectations rewritten.

## 2026-09-30 — League-tuned openings made Hard easier for a strong player: the league's fitness never rewards stopping the leader
Final Hard v2 validation (docs/sim-results/2026-09-30-hard-v2-validation.md, 400 Standard games per row): a Snowball or GreedyExpand challenger seat won more often against seven Hard v2 AIs than against seven old Hard AIs (GreedyExpand 13.5% → 18.2%, sign test p = 0.05), one Hard v2 seat won 10.8% against old Hard (parity 12.5%), and on the user's playtest-3 map seat 0 never won against old Hard (0/56) but won 9–15/56 against Hard v2. The cause is visible in the war counts: old Hard declares about 20 wars per game and 25.6 per game on a leading Snowball seat; Hard v2 declares 13 and 12–14. The league scored each opening by its own wins and VP share, so its equilibrium favours openings that keep to themselves; the old scripted Hard's dogpile on the leader is what a human feels as difficulty. Lessons: measure a candidate AI with a human-style challenger against the table (not only AI-vs-AI win rates), and give a league a leader-containment term before expecting "harder". Also: capping DefendedExpand's draw share from 40% to 25% cut the length excess from +12.5% to +8.8% (each DefendedExpand seat adds about 9 turns), and a 2-turn Defend hysteresis cut phase flapping (max switches 57 → about 33) without changing stalls (1 vs 1 per 400 games).

## 2026-09-30 — Decision: playtest-4 keeps the scripted Hard; the next league needs leader containment and an anchor opponent
Hard v2 is off in the app (`legatum_wasm::session::make_brain` plays the scripted Hard) and available only behind the `hard-v2-ai` setup switch (`legatum-sim --hard-v2`); city strike stays a default rule. The overnight league optimised each opening's own win rate and VP share against other league openings, so it produced a varied but passive table: fewer wars, and no dogpile on the leader, which is exactly what a human experiences as difficulty. For the next league, the fitness needs (1) a leader-containment term (reward the table for denying the VP leader, not only the seat for its own score) and (2) anchor opponents that stay fixed, the scripted Hard and a strong human-style challenger (the Proxy, tuned Snowball/GreedyExpand seats). Accept a candidate only if it beats the scripted Hard head-to-head and lowers the challenger's win rate (`legatum-sim --challenger <Opening> [--hard-v2]`, 400 Standard games, same seeds), not on league equilibrium metrics alone. A switch that changes which brain plays belongs in the setup (it travels in saves and tapes, so a reload recreates the same brains).

## 2026-09-30 — Why the overnight opening league underdelivered
Full analysis: ~/LegatumData/analysis/playtest3/why-evolution-underdelivered.md.
- Search budget: round-robin tuning gave each opening about 19 CMA-ES steps at Quick and about 5 at Standard, against the hundreds to thousands that 48 noisy dimensions need. Population 8 was about half the textbook default (~15).
- Noise: genome identity explained about 19% of a candidate's fitness variance, the map about 13%, and the 8-player opponent, seat and faction draw about 67%. The winner's curse overstated gains in 83-88% of tests (train +0.05 vs held-out +0.02).
- Objective: fitness was relative (openings vs each other), so leader containment, which is what makes the scripted Hard hard, was never rewarded.
- Next time:
  - train in 1v1 small-map mirrored duels, and confirm in 8-player games before shipping;
  - tune openings concurrently, not round-robin;
  - use a population of about 15 with racing and resampling;
  - use MAP-Elites per opening;
  - add exploiters to the league;
  - include fixed anchor opponents (the scripted Hard plus a human-style challenger) in the fitness.

## 2026-09-30 — The league's tuned "Rush" never rushes: relative fitness collapses opening identities
In 200 Standard duels (tuned genomes, ~/LegatumRuns/duel-sweep/base) Rush declared no war in 96-99% of games and captured no city in any game; every game ended on VP. The active tuned Rush genome has `rush_timeout = 10`, the gene's minimum. Scaled x2 at Standard, `phase_for` in crates/ai/src/openings.rs abandons the rush at turn 20, before the first Soldier finishes (~turn 21). The overnight league optimised win rate with no identity constraint, so CMA-ES turned Rush into a slow expander. That is why "Rush" numbers across the whole league and duel work say nothing about rushing, and why early-military discounts and turning off city strike changed nothing (combat never happened). Related: the tuned `snipe_settlers_weight` is near max, but `snipe_settlers_radius = 1` makes it dead. Rule for future tuning: each opening needs identity gates (e.g. Rush must declare war and reach an enemy city by a set turn in most games, measured in telemetry), enforced as a constraint on candidates, not left to fitness. The built-in Rush (timeout 80) also loses ~98% to GreedyExpand, so the attack behaviour itself needs work too. Details: ~/LegatumData/analysis/duel-rush-vs-greedy.md.

## 2026-09-30 — Built-in Rush can't rush either: primitive war planning shadows the opening's war logic
40 built-in Rush vs GreedyExpand duels: Rush won 2.5%, declared war in 20% of games (always after abandoning the rush, mean turn 127), captured nothing, and stayed at 1 city for ~160 turns while its 160-turn timeout held the economy hostage. Causes in crates/ai/src:
- `plan_primitive_war()` always claims declarations because `PrimitiveParams::default()` weights are non-zero, so `plan_opening_war()`'s muster/`war_army` logic is dead for every non-Default opening, and primitives have no minimum-force gate.
- `strike_target` is only read by gold buying. Marching uses `campaign_target_for()`, gated on aggression and unaware of the declared target.
- `Phase::Conquer` needs `conquer_cities` cities, which a one-city rush never has.
Lesson: when a layered system (openings → primitives → campaign) gets a new layer, test that the old layer's decisions still reach the executor. Being "tuned" hid dead code. Fix queued as Astra `real-rush`. Analysis: ~/LegatumData/analysis/duel-rush-vs-greedy.md.

## 2026-09-30 — Opening identities are shadowed across the board, not just Rush
Astra's read-only audit (.reviews/astra-opening-identity-audit.md; gate rates in docs/sim-results/2026-09-30-duel-identity-gates.md) found the same pattern in every opening. Shared primitives run first and claim the decision even when they do nothing:
- `plan_primitive_buy()` returns true without buying, so no opening's `burst_buy`/`gold_save` ever runs.
- Primitive escorts ignore `WaitForEscort` and `EscortPolicy::None`, and release escorts before founding.
- Primitive buys and victory investments ignore settler targets, so Tall has no real city cap.
- `primitive_production_bonus()` subtracts the predecessor tier's gold, although core stacks tier yields: a Clearinghouse is valued at 1 gold instead of 4.
The existing opening escort test builds a planner without primitives, so it tests a bypassed path. Tall's ongoing strategy weights favour food and industry 4x, so its science stays at about 11 against Default's 25. Lesson: tests for a layered AI must run the production dispatch path (all layers on), and every tunable gene needs a test that it changes behaviour.

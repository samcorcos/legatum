# Faction heraldry

Eleven peoples, one set. Every mark is generated by code from one charge per people, so the crest, the seal and the glyph of a faction always show the same object and all eleven share one ring, ground and engraving language. The charges are historical (H1–H8 approved by the user on 2026-10-31, `docs/design/heraldry/historical-charges-2026-10-18.md`; India, the Aztecs, Egypt and Rome designed to match on 2026-11-21). The earlier painted crests and their prompts (a listening dish, a crystal tree, brood cells and the rest of the retired setting) were removed on 2026-11-21 and are in git history.

Three tiers of faction marks, one per use:

| File | Size | Use |
| --- | --- | --- |
| `raster/crest-<faction>-512.png` | 512 px | Grand screens: faction select, victory, game setup. The seal struck in gold on navy, not tintable. |
| `seal-<faction>.svg` | viewBox 512 | Player-colored in-game seal: victory race header, city banners, diplomacy, tooltips at 40 px and up. |
| `glyph-<faction>.svg` | viewBox 24 | Inline mark at 16–24 px: VP track rows, lists, unit plates. Answers to the icon name `faction-<faction>`. |

Faction ids: `switzerland`, `india`, `byzantium`, `germany`, `celts`, `mongols`, `sparta`, `athens`, `aztecs`, `egypt`, `rome`. All eleven take the same path in code (`data.ts` `factionInfo`, `brand/ornaments.tsx`, `icons.ts`): no faction borrows another's mark or falls back to a different tier.

Rules for a charge: one historically grounded object, alone in the field; generic rather than any one state's arms; no modern national flag or emblem; nothing taken from another game's faction icons. H2 (a torii for Japan) is unused: Japan is not a playable people.

## Seals

- Single ink: everything is `currentColor` (solid relief, a 50% half-tone, a faint field tone and engraved hatching). Set `color` on the element or a parent to tint it in the player's color.
- Inline the SVG (e.g. `?raw` import) or use it as a CSS mask (`FactionSeal`) so the tint applies. As an `<img>` it renders black.
- Engraved lines are cut out through an SVG mask, so the seal shows whatever is behind it through the cuts; it works on any background, best on dark panels.
- Every id is prefixed `seal-<faction>-`, so all eleven can be inlined in one document.
- Shared rim on all eleven: double ring, pearl band with house stars at the quarters, and the four-point house star crowning the rim (as in the logo).
- Detail is drawn for 128 px and up. At 40–56 px the hatching becomes tone and the charge still reads; below 40 px use the glyph.

## Glyphs

- `fill="currentColor"`, no ids, no masks. Each is the seal's charge as a solid silhouette with knocked-out detail that holds at 16 px (the owl's eyes, the helmet's eye and cheek slit, the gap of the torc). A glyph keeps one idea; the seal carries the detail.
- The eagle is drawn once on the 24 grid (`EAGLE` in `build-seals.mjs`) and enlarged for the seal, so the two cannot drift apart.

## Crests

The crests are not paintings. `render-crests.mjs` lights each seal as a gold bas-relief with an SVG lighting filter (the seal's ink is the height map) over one shared navy ground, and screenshots it at 512 px in headless Chromium. Ring, ground, light and margin are therefore identical for all eleven. There are no prompts to keep: the charge code is the source.

The roundel that shows a crest crops it to a circle at 104% (`styles.css` `.crest img`), so the script keeps the rim and its star inside 92.5% of the canvas.

## Regenerating

```
node app/src/assets/heraldry/src/build-seals.mjs [faction]     # seals and glyphs
node app/src/assets/heraldry/src/render-crests.mjs [faction]   # crests, from the seals
python3 tools/art/distinctness.py --render --check             # glyphs at 16/24 px, seals at 40/56 px
```

Edit the charge functions in `build-seals.mjs` (not the SVG output). `build-seals.mjs` has no dependencies; `render-crests.mjs` needs Playwright's Chromium (from `app/node_modules`, or set `LEGATUM_ART_NODE_MODULES` to a folder that holds `playwright`). Look at every glyph at 16, 24 and 48 px and every seal at 40–56 px before committing: a charge that only reads at 200 px is not finished.

## Reward emblems

Celebration cards show a per-kind emblem instead of the faction seal (art pass, 2026-10-05). They live beside this folder in `app/src/assets/rewards/` and share this folder's engraving kit:

- `heraldry/src/kit.mjs` holds the geometry helpers, path transforms, the `Seal` canvas (solid, half-tone, tone, hatch, cut, shade) and `laurel`; `build-seals.mjs` and `rewards/src/build-rewards.mjs` both import it (importing it writes nothing).
- `node app/src/assets/rewards/src/build-rewards.mjs [kind]` writes `emblem-<kind>.svg`: camp, ruin, captured, founded, growth, milestone, greatwork, tech. Edit the charge functions there, not the SVG.
- Same rules as the seals: one ink in `currentColor`, ids prefixed `emblem-<kind>-`, inline or use as a CSS mask (`RewardEmblem.tsx` masks it in the card's medallion ring). Unlike a seal an emblem has no rim and its `viewBox` is cropped to the charge. Drawn for 96 px and up; the charge, not the hatching, must carry it at 56 px.
- Mask gotcha: an engraved cut removes everything drawn before it, including later shapes that have no `halo`. A part drawn after a `cutFill` over the same area needs `halo: 1` or more to show again.
- Which kind means what: see the legatum-art skill (Reward emblems).

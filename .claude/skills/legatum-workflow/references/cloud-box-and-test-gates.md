# Workflow: cloud build box, test gate profiles and public-repo rules

The cloud build box, the no-daily-cap ruling, player text in briefs, the AI-impact gate, open-source rules, release note checks, and the fast/extended/release verify profiles.

Moved verbatim from SKILL.md on 2026-11-22 (original order kept). The current rules are in SKILL.md; where this file disagrees with SKILL.md, SKILL.md wins.

## Cloud build box (user, 2026-10-10: "yes use a cloud verify box"; infra/cloud-box, tools/cloud)
A stopped-when-idle Graviton machine (c8g.16xlarge, 64 vCPUs, spot) that takes heavy compile, test, WebKit and sim-build work off the overloaded Mac. It starts on demand (about 1 to 2 minutes cold), stops itself 20 minutes after the last job, has a hard 8 h/day cap enforced from AWS, no inbound ports (ssh over SSM) and no GitHub or user credentials: code travels as a git bundle through S3.
- **Prefer remote for verification, sim builds and WebKit.** `tools/cloud/verify-remote.sh <branch> [--duel] [--app] [--no-cache] [--webkit]` runs `verify-branch.sh` on the box and prints the same summary (logs in `.progress/verify-remote/<branch>/`; exit code is verify's). `tools/cloud/build-linux.sh` builds the sim binary on the box by default (local Docker only when `LEGATUM_CLOUD_LOCAL_BUILD=1` or the box is unavailable). `tools/cloud/webkit-remote.sh <worktree|ref>` runs Playwright WebKit natively on the box; it replaces `tools/release/webkit-docker.sh` for ad hoc runs (the release check still uses the Docker script).
- **Anything else:** `tools/cloud/remote.sh <worktree-path|ref> [--with-uncommitted] [--artifact PATH]... [--npm] -- <command...>` ships that exact commit (plus the working diff and untracked files with `--with-uncommitted`), runs the command in a per-job slot checkout (up to 12 at once (since 2026-10-18), each with its own warm cargo `target/`), streams output, copies named artifacts back and exits with the command's exit code. Ctrl-C or a killed wrapper kills the remote job; `--attach JOB` and `--kill JOB` manage a job after a dropped terminal. Exit 3 means the box could not be used (capacity, credentials): fall back to local, or wait.
- **No wait without a deadline (user, 2026-11-08: "ensure that does not happen again", after a box job hung six hours overnight and stalled the landing queue).** `remote.sh` (and so `verify-remote.sh`) now puts a hard deadline on every short ssh call (`LEGATUM_BOX_SSH_DEADLINE`, 300 s; exit 3 if the upload or start hangs) and ends a follow that has printed nothing for an hour once the job's process is gone or the box does not answer (`--stall`, `LEGATUM_BOX_STALL_SECS`; exit 124, job left attachable). Agents' own wait loops (`until grep ...; do sleep; done`, Monitor conditions) must also carry a deadline, about twice the job's usual wall time, and report when they hit it instead of waiting on. A landing coordinator that waits on another agent checks that agent's last activity at least hourly and reports a stall to the lead.
- **Rules:** run it for gates and builds, not for Mac-only work (anything needing the display, such as `tools/ui/webkit-mac/check.sh`). A box job is "free" CPU for the Mac but costs about $0.73 an hour while it runs, so don't leave the box up: it stops itself, and `tools/cloud/box.sh status` (also shown by `tools/cloud/status.sh`) tells you. Sims still go to the spot servers (`run-batch.sh`), not the box.
- **Verification results differ slightly from local:** the box is Linux (Ubuntu 24.04) with its own toolchain installed to the Mac's `rustc` version; step timings are logged to the local ledger as kinds `verify-remote`, `box-verify` and `box-<kind>` so `tools/ops/timings-report.py` can compare them with local runs. The box keeps its own gate cache, separate from `~/LegatumRuns/gate-cache`.
- **Measured (2026-10-10):** a full `--app` verify took 31.6 min on the box against 93.6 min locally (the Playwright step, about 20 min, is serial and the same either way); a verify without `--app` takes about 8 min against 73 min locally. Cold start of a stopped box is about 1.5 min.
- **Operations:** `tools/cloud/box.sh start|stop|status|shell|prepare|warm|jobs|gc|sweep|util`. `box.sh warm` rebuilds master's artifacts in the golden slot (run after toolchain bumps or big dependency changes; new slots seed from it). Infrastructure changes go through `infra/cloud-box/tf.sh` and need the lead to ask the user.
- **Box health, queue and throughput (2026-10-18; runbook `docs/ops/cloud-box.md`):** a stalled gate with a long queue and low load is a jam (locks, slots, disk), not missing CPU: `box.sh status` shows slots busy, queue length, disk and CPU utilisation per hour. Lock waits check that the holder is alive (`tools/astra/lockdir.sh`); `box_sync` only moves the box scripts forward along master (`LEGATUM_BOX_SYNC_FORCE=1` for unmerged box scripts); `/data` is 600 GB with 12 slots, each trimmed to 34 GB after its job (`box.sh sweep`); plain `cargo test` on the box runs as nextest plus doctests (`LEGATUM_BOX_NO_NEXTEST=1` opts out). **Idle filler (user, 2026-10-18: "run all 64 CPUs at 100%"):** pure-CPU, rerunnable batches (AI optimisation arms, combat-lab sweeps, benchmark arms) go to `tools/cloud/filler.sh submit SPEC.json [--commit REF]`; they run at the lowest CPU weight so real jobs always win, and the box stays up while they exist. Use unique ids (the box role cannot delete from S3).


**Cloud box: no daily cap (user, 2026-10-11):** "Can we just not have a cap on this? use it when we have too much load." daily_cap_hours = 24 (the client default LEGATUM_BOX_CAP_MIN is 1440). Idle auto-stop (20 min) and the monthly budget are the guards. Prefer the box for any heavy work. Applying it needs `aws sso login --profile <admin-profile>` and `-var ssh_public_key=...`.

**Player-facing text in briefs (user, 2026-10-17):** any agent brief, Claude or Codex, whose task writes or changes text a player reads must include this line: "Follow the plain-language guide in `.claude/skills/legatum-ui/SKILL.md` (Game text: plain language, with its glossary), and `npx vitest run src/ui/textArtifacts.test.tsx src/ui/copySource.test.ts` must pass." Agents had been translating code into rule text ("per complete pair" for `pop / 2`).

**AI-impact gate (lead, 2026-10-11, after A2 halved Hard's win rate):** any branch that changes units, buildings, techs, factions or rules ships with AI support (the AI values and uses the new content, informed by combat sims) and runs the human-seat benchmark (seat-only and opponents-only, against the master control) before landing. A significant drop blocks landing unless an AI fix lands with it. Briefs for content changes must say this. The daily `legatum-ai-research` director checks that nothing slipped through.

**Battery rule (user, 2026-10-11):** "My battery is consistently at 7% because the CPU is running too hard... get the battery up to at least 50%." No heavy local CPU. Builds, tests, clippy, WASM and Playwright run on the cloud box (`remote.sh`, `verify-remote.sh`). Sims and benchmarks run on AWS spot (`run-batch.sh`). The Mac edits, merges and reads results. Codex lane builds are being routed to the box (the offload-lanes agent). Lanes are capped at 1 until that lands.

**Open source within weeks (user, 2026-10-11):** the repo will be public on GitHub. Keep it professional:
- commit only what belongs, and gitignore the rest;
- delete dead code;
- keep README, ARCHITECTURE and the docs current;
- add no secrets or personal details to repo files.
- **What stays public and what never goes in (user, 2026-11-21, before going public):** keep the design reasoning, learnings, plans and the AI workflow public so people can learn from them ("don't scrub too much"). Leave out only personal details (people are named by role: the designer, the co-op partner, the second player), account and machine identifiers (account ids, profile and user names, addresses, device models), and budget or spending notes (bills, caps, subscription usage). Record the lesson without the number: "an idle box ran up a large bill", not the amount.
- **A scrub list never contains what it scrubs (2026-11-21):** tracked files hold only generic patterns (`tools/release/scrub-patterns.txt`); the specific values to hide live in the git-ignored `.private/scrub-patterns.txt`, and per-machine cloud names and limits in `.private/cloud.env` (shapes in `.private.example/`). Never write such a value in a test, a comment, a commit message or a learnings entry, even obfuscated or in part. `tools/release/test-scrub.sh` (also in CI) fails when the tracked tree matches a pattern.

The engine, sim, rules and benchmark and scenario methodology should double as a learning resource for building games and running simulations. The hourly supervisor audits each hour's commits.

**Check release notes against the tag (2026-10-11):** the 8.9 release agent's "what's new" listed the crown rule, unlock art and era silhouettes, which weren't in the build (docs commits made them look landed). Before telling the user what's in a build, check each feature branch with `git merge-base --is-ancestor <branch> playtest-N`.

**Release check via the box (2026-10-11, 8.9.1):** running `tools/release/check.sh` through `remote.sh` writes its post-`cd app` steps to `app/<log>`, because the log path is relative, so the printed summary is partial. Pass an absolute log path. Tablet-touch layout specs aren't a release gate for the user's desktop builds; report them, but don't block on them.

## Test gates and verify speed (D13, 2026-10-18)

Three profiles, one flag: `tools/cloud/verify-remote.sh <branch> --profile fast|extended|release` (and `tools/astra/verify-branch.sh --profile`). Without a flag a change that touches no Rust runs **fast**, anything else **extended**; **release** is always explicit.

| Profile | Rust | Playwright | When |
| --- | --- | --- | --- |
| fast | fmt, clippy, build, repin, smoke and every test except the long ones in `tools/astra/extended-rust-tests.txt` | smoke set: `game`, `turn-flow`, `research-click`, `production-picker`, `exit-to-title` | app-only, docs and tool branches; every Codex/Claude branch before landing |
| extended | the whole workspace (nothing deleted) | every `e2e/*.spec.ts`, but not the screen tour | any branch that touches `crates/`, `scenarios/`, `.config/` or the Cargo files (the default for them) |
| release | as extended | everything including the two-size tour (`e2e/tour/*`), plus WebKit (`--webkit`; `tools/release/check.sh` runs it natively on the box) | playtest builds, UI-reviewer runs, `master` health |

- **Failure policy.** Assertion, timeout and unclassified failures are never rerun: they fail the gate. A Playwright run whose failures are *all* browser transport errors (`net::ERR_NETWORK_CHANGED`, a closed browser; classified by `tools/ops/pw-summary.py`) reruns only the failed tests once (`--last-failed`); the summary shows the first run, the rerun and the error classes. A branch that fails fast is not retried at extended; fix it. If fast passes and extended fails, the failure belongs to the branch (the profile only adds tests), not to flakiness, until a rerun proves otherwise.
- **The tour is split by domain:** `app/e2e/tour/{title-lobby,turn-one,diplomacy-war,combat,research-unlocks,victory-race,factions,yam-relay,post-game,first-run-hints}.spec.ts` share `helpers.ts`. Run one with `npx playwright test e2e/tour/combat` (on the box). Shots land in `test-results/screen-tour/<size>/<domain>/`; `LEGATUM_TOUR_OUT` moves them. A new screen joins the domain it belongs to.
- **Why the Rust test step took 5 minutes:** one test (`opening_league_twenty_standard_games...`, 280 s on a single thread) was the whole critical path of 570 s of test work. It now plays its 20 games side by side, nextest starts it first (`.config/nextest.toml`), and fast skips it. Re-measure with `python3 tools/ops/rust-test-durations.py .progress/verify-remote/*/steps/test.log`.
- **Artifact steps never hit the gate cache:** `app-wasm` and `app-build` produce files in the worktree, so a PASS record from another slot must not skip them (CL6). The WASM build has its own exact-input cache (key narrowed to the crates the WASM actually compiles) that restores the package and hash-checks it against its manifest.
- **Playwright workers.** A box job's workers follow its core budget (`tools/cloud/box/budget.sh`); the 2026-10-18 sweep (`docs/ops/test-gate-timings.md`) found Chromium wall time flat from 12 to 48 workers on a busy box and failures growing with the count, so more workers than cores buy nothing. WebKit (release) runs 8 workers natively on the box (`LEGATUM_WEBKIT_WORKERS`), 2.3x faster than 4; `tools/release/check.sh` on the box runs it beside Chromium instead of in a 1-worker Mac container (that was 56 of the release check's ~60 minutes). Rerun `tools/ops/pw-sweep.sh chromium|webkit N...` in a quiet hour to refine.
- **Sharding one verify (`--shards N|auto|1`):** a main job (Rust, WASM, tsc, vitest) plus N Playwright shard jobs, merged into one summary. `auto` shards only with 3+ free slots and no queue. Sharding does not create CPU: on a saturated box the shards queue like any job.

## A supervisor that only reports to the lead fails when the lead does (user, 2026-11-21)
On the first night of the survive-him program all agents and Codex tasks finished within four hours, then nothing ran for six: the lead session hung mid-turn (a 25-second command returned eight hours later, cause unknown). The scheduled supervisor flagged the stall three runs in a row, but its only output was a list for the lead, and its push to the user was skipped. One kept fix sat unmerged for seven hours and 62 points of weekly budget went unused. The user noticed first: "i noticed that you used very few tokens... so i suspect it didnt work". Rules: (1) a supervisor must have a way to keep work moving that does not pass through the lead (queue Codex follow-ups, restart lanes) and a way to reach the user that does not depend on the lead's terminal; (2) low token use overnight is itself the alarm: report usage burn in every status, and say "idle since HH:MM" plainly; (3) the lead ends every evening turn with the next round already queued, never waiting on its own wake-up; (4) widening a scheduled task's authority needs the user's explicit yes (the auto-mode classifier refused the lead's attempt on 2026-11-21).
- **He stopped the program and wants it in a "project" (user, 2026-11-21):** "ok lets stop it. i want to move this to a 'project' because it seems like that's more stable". What he values is that long-running work keeps going without a single session as its weak point.

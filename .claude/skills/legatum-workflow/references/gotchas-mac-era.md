# Workflow: gotchas, the Mac battery rule and AWS approvals

Gotchas that cost time (many are Mac-, Tauri- or Codex-lane specific and historical since 2026-11-22), the lane cap, the battery rule, Terraform approvals and the AWS budget.

Moved verbatim from SKILL.md on 2026-11-22 (original order kept). The current rules are in SKILL.md; where this file disagrees with SKILL.md, SKILL.md wins.

## Gotchas that cost time
- **A decided feature isn't done until it's on master (2026-10-31).** The designer chose India on 10-25. Codex built it on `astra/india-regional-courts` on 10-26, but nobody merged it, and the held Tokugawa Japan task waited on it for five days until he asked "did we implement everything that we discussed and agreed to?". Every write task that finishes gets a next step the same day: merge, fix, or a recorded reason to park it. Held tasks name what releases them, and the ops check lists `astra/*` and `claude/*` branches with unmerged work older than 24 hours.
- Astra's sandbox can't launch a browser, so its UI work is never visually verified. Never merge UI from Astra on its word: Claude takes Playwright screenshots at the user's window size (~1000x600 CSS at 2x on their laptop) and looks at them first. Better: give UI work that needs taste to a Claude agent. (Playtest-6 shipped an unverified tech panel with the same overlap bug, an illegible current-research card and still-boring cards.)
- **Merge master into a held train before re-verifying (2026-11-01).** `verify-remote.sh` merges master into the branch first, so even one new progress-log line on master makes it fail in two seconds on a conflict. Merge master into the train branch yourself first.
- macOS /bin/bash is 3.2: no associative arrays, broken `source <(...)`; zsh doesn't word-split `$var`. Use `case` functions and `bash -c`.
- A long-running bash reads its script incrementally: never edit a running script in place; write a new file and `mv` it over.
- Remove worktrees with `git worktree remove --force`, not by deleting the directory.
- The disk watcher (`tools/cleanup/disk-watch.sh`, run with AUTO_APPLY=1) removes merged, clean, idle, unlocked worktrees every 30 minutes. Since 2026-10-03 it does this regardless of free space, after 86 stale worktrees piled up and broke agent spawns. Keep it running, and remove an agent's worktree right after merging its branch.
- legatum-sim defaults to Normal difficulty; pass `--difficulty hard`. `start-settlers=N` means N extra.
- Identical results across conditions mean a harness bug, not a finding.
- Validity measured with a weak member (e.g. Tall) props up everyone else's "beats at least one".
- A new decision screen joins the screen tour, with a fixture, in the same change that adds it. Byte-diffing tours between releases is useless (about 3% of shots identical, because of timestamps), so the reviewer reviews by changed feature plus a full look. A per-screen pixel diff against the prior release (over 1% means look closely) is the changed-or-not test. Playwright wipes `test-results/` on every run, including `-g` runs: copy `app/test-results/screen-tour` to the archive right after the full run. The reviewer compares against a baseline tour of the previous release, and unchanged screens should be pixel-identical.
- **Safari runs WebKit, and our Playwright suite runs Chromium.** "Exit to title" did nothing in the (since dropped) Mac app's WebKit view because WebKit fires `blur` with `relatedTarget: null` when focus moves between buttons in the same menu, and GameMenu closed itself mid-click. Chromium passed. The release check runs the screen tour and the menu spec in WebKit too (`LEGATUM_E2E_BROWSER=webkit`). Reproduce "works in tests, broken in Safari" bugs in WebKit first. **Never run Playwright WebKit on the macOS host, not even in the release check** (2026-10-05, and again 2026-10-07 at one worker): its screenshots go through WindowServer, which accumulated 46k capture surfaces (55 GB) across many agents' runs and aborted twice in 9 hours, logging the user out and killing every app. `app/playwright.config.ts` refuses host WebKit outright, `tools/release/check.sh` runs WebKit only through `tools/release/webkit-docker.sh` (a Linux container), and `tools/ops/no-host-webkit.sh` (kept alive by the watchdog) kills any host WebKit within 10 s. Run it with `tools/release/webkit-docker.sh <worktree>` (needs the worktree's built `app/dist` and Docker Desktop; about 35 min for the two specs at `--cpus=4`, results in the worktree's `app/test-results`; `LEGATUM_E2E_BROWSER=chromium` runs the same container with Chromium to tell a WebKit-only failure from a test failure). Landing and task gates use Chromium only; reproduce a WebKit-only bug in a Linux container or ask the lead. Playwright tests the built `app/dist`, so run `npm run build` (after the WASM build) before every Playwright step: a stale dist gave 3 false failures in the goal-AI landing (2026-10-05). A landing gate's Playwright run includes `layout.spec.ts` (every faction sheet fits at 1000x600), not just the screen tour: on 2026-10-05 one longer Sparta card line overflowed by 9 px, and landing 1's gate missed it.
- Layout tests must include a two-human state; single-player layouts hide seat-row overflow.
- In agent worktrees the guard rejects `nice -n 15 npx ...`; run heavy builds through a script that calls `renice 15 -p $$` first.
- Spawning several worktree-isolated Claude agents in one message races in git and leaves broken stubs; spawn them one per message. Clean stubs with `git worktree unlock`, `git worktree remove --force`, `git worktree prune`.
- If isolated agent spawns fail ("git could not be run to resolve it", usually at high load), create and lock the worktree yourself, then spawn a non-isolated agent pointed at it.
- Sanity-check every scenario: a perfect player can meet the objective, it isn't met or failed on turn 1, and its targets are marked on the map from turn 1 (a human lost The Courier King only because the target was hidden).
- **Run at most about 5 Claude agents at once.** About 12 concurrent Opus agents exhausted the Claude Max session limit and all died (2026-10-03). Prefer lead-created worktrees (`git worktree add` plus `lock`, then a non-isolated agent pointed at it): unlike `isolation: worktree` agents, they can be resumed with SendMessage after a failure. Give simulation-heavy and mechanical work to Astra.
- After a reboot or agent crash, `git worktree` locks naming a dead PID ("claude agent ... pid N") are stale and stop the cleanup script from reclaiming merged worktrees. `tools/cleanup/unlock-stale-locks.sh --apply` clears them; the disk watcher runs it every cycle (user-approved 2026-10-04).
- **Budget pacing (user, 2026-10-04; updated 2026-10-18):** pace Claude usage to the weekly reset. Extra usage is now on with a hard cap that the user won't raise ("I don't want a bunch of partial tasks that die 80% of the way through"). Check `get_usage` (weekly % and `extraUsage.spent`) and Codex's `rate_limits` before starting any agent; on extra credits, finish in-flight work and start only what can finish. Near a limit, switch to token-free CPU/GPU work (sims, builds) and Codex tasks.
- Every sim, Astra's included, uses the default `LEGATUM_RUNS=~/LegatumRuns`, so baseline builds and caches are shared. Don't put a custom runs root in task prompts.
- Agents must keep scripts in their own scratchpad subfolder (scratchpad/<task>/), never shared names like scratchpad/nice.sh. One agent overwrote another's helper and ran tests in the wrong worktree.
- **Sub-agents don't file suggestion chips** (spawn_task) for the user (2026-10-05: the user started three chips thinking the lead recommended them). They list follow-ups in their final report; the lead triages them and queues work or asks the user. Only the lead files chips, and only when it means to recommend the work.
- **Agents verify UI with headless Playwright only, never the Claude app's built-in browser pane** (mcp__Claude_Browser__*). A hidden pane tab of the game kept playing music after the user quit the game, twice on 2026-10-04. Playwright runs are silent (navigator.webdriver).
- **Clean up after browser work:** close any tabs opened in the Claude app's browser pane and stop any dev server or `wrangler dev` relay you started. A hidden tab kept playing the game's music (2026-10-04).
- **Never amend or force-push a branch once another agent may have merged it.** Add a new commit instead. The lead amended claude/exit-and-growth-label after the landing agent had merged the old tip, and the landing agent had to hand-port the fix.
- Describe AI build orders from tapes, not configured lists (locked items fall back to something else).
- **Gate the merged result before fast-forwarding master** whenever both sides changed crates, even if each side passed its own gate (2026-10-06: sim-speed increment 5 fast-forwarded first and gated afterwards; it passed, but the order was wrong).
- **A crates-only change still needs the app's tests:** the WASM build plus full vitest, because new view fields can break TypeScript consumers. On 2026-10-06 AI speed pass 1 was gated on cargo only and shipped a view mismatch (`buy_block`, `known_by`).
- **A gate script must fail on any failing step** (`set -e`, or check each exit code), and the lead checks every step's status, not only the FAILED/panicked lines or a done marker. On 2026-10-06 AI speed pass 2 landed with a failing clippy step, because its gate printed a done marker regardless.
- **Cloud builds of several checkouts share one cargo volume and one mtime test** (2026-10-06). `tools/cloud/build-linux.sh` mounts each checkout at `/src` over the same cached target volume; a checkout whose files are older than the previous build's outputs is not rebuilt, so an "after" binary came out identical to its baseline. Identical results across conditions mean a stale binary: `find crates -name '*.rs' | xargs touch` before every build in a different checkout. Never run `docker kill` on every container (`docker ps -q | xargs docker kill`): other agents' builds share the daemon.
- **Never use `git stash`.** The stash is shared by every worktree, and on 2026-10-06 one agent's `stash pop` applied another agent's WIP. Set work aside with a WIP commit on your own branch.
- **Rules first, then heavy simulation; CPU over tokens (user, 2026-10-06):** land the decided game changes before large AI tuning sweeps, since rule changes invalidate tuning. Be smart with tokens: if spending more CPU or cloud time (long gates, big batches, letting tests find problems) saves tokens, do that.
- **Check `ListAgents` before re-spawning any work.** Nested sub-agents outlive their parent and stay reachable by name. A quiet worktree, or a parent's "no live children" note, doesn't mean they died (2026-10-06: duplicates collided in goals-2).
- **Freeze master for a big ready branch.** Tell other agents not to fast-forward until it lands, or it re-merges after every landing (goals-2 merged three times on 2026-10-07).
- **Playtest releases are playable-build-first (2026-10-07):** when every landed branch has passed its own gate, publish the preview (`scripts/deploy-preview.sh`), then run `tools/release/check.sh` in the background, and ship anything it finds as a follow-up preview. A warm release check takes about 17 minutes; it reached about 50 minutes only under heavy load, cold caches or WebKit. Pause other agents' heavy work while releasing. The release WebKit step should run only the WebKit-specific specs (exit-to-title, the turn-1 panel), not the whole tour.

**Lane cap and the Mac's CPU (2026-10-10):** `echo N > .progress/astra-queue/max-lanes` stops lanes above N from taking new tasks; each finishes its current task first. Delete the file to uncap. At load 89 on 16 cores, the user wants work offloaded to AWS (a cloud build box is being built), not more local parallelism. Another project on the same machine has Codex runner loops, but they're idle when its queue is empty (0% CPU, polling every 30 s). Don't blame them for load without measuring (corrected by the user, 2026-10-11). Check per-process CPU before attributing load.

**Battery rule: no heavy CPU on the Mac (user, 2026-10-11):** the laptop's battery sat at 7-8% under a load of about 78 on 16 cores; he wants it at 50% or more. Heavy work goes to the cloud build box or AWS spot, and Claude agents obey it as much as Codex lanes:
- **Codex lanes do it automatically.** `runner.sh` gives every write task `LEGATUM_OFFLOAD=1`, a PATH of shims (`tools/astra/lane-bin`) and a ZDOTDIR (`tools/astra/lane-zsh`; Codex runs `zsh -lc`, which reorders PATH and would otherwise put the real `npx` first). Forwarded to the box through `tools/cloud/offload.sh`: `cargo test|nextest|clippy|check`, `npx vitest|tsc|playwright`, `npm test` / `npm run build|e2e`, and the scripts that offload themselves (`tools/sim/repin.sh`, `scripts/build-wasm.sh`). Same output stream, same exit code; every non-ignored file the command added, changed or deleted is applied back to the lane worktree (fixtures, `pins.json`, `Cargo.lock`), and git-ignored outputs only when named with `--artifact` (build-wasm returns `app/src/wasm-pkg`). A command that ran on the box and failed keeps its failure; the box being unusable (exit 3, daily cap, no credentials, job never started) runs it locally under `nice -n 15` instead, remembers that for 10 minutes (1 hour for the daily cap) in `~/LegatumRuns/box/offload-unavailable-until`, and never fails the task. Kill switch: `touch .progress/astra-queue/no-offload`.
- **Stays local on purpose:** `cargo build` and `cargo run` (their binaries run on the Mac afterwards), `cargo fmt`, `wasm-pack`, `npm ci`, anything run by path (`target/release/...`). Those run niced; keep them small. Do not write tasks that build and run large local sims.
- **Sims and benchmarks go to AWS spot.** `tools/sim/hard-vs-human.sh` now defaults to the cloud when AWS credentials work (the build on the box, the games on one spot server; `--local` only on request). Task prompts say "run it in the cloud" and never `--local` or `RAYON_NUM_THREADS=4 hard_vs_human`. Other sims: `tools/cloud/run-batch.sh`; anything else that must run on the box with outputs back: `tools/cloud/remote.sh . --with-uncommitted --artifact <path> -- <cmd>`.
- **Claude agents and the lead:** use `tools/cloud/verify-remote.sh` for gates, `remote.sh` for other heavy commands, never a long local `cargo test --workspace`. Check `uptime` and `pmset -g batt` before starting heavy local work; the user's laptop is often on battery.
- **Cost:** the box runs only while jobs run (stops 20 minutes after the last one) at about $0.73 an hour on spot, shared with every other box user (no daily cap since 2026-10-11; the monthly budget is the guard). Each forwarded command costs about 25 s of overhead (bundle, upload, slot checkout, artifact sync) on top of the run, so a task that runs a dozen tiny cargo checks pays minutes; batch checks into one command.

**Terraform applies need the user's yes on the specific plan (2026-10-10):** approving an infra idea in general ("yes use a cloud verify box") is not enough. The auto-mode classifier blocked the lead from passing apply approval to an agent. Present the plan summary (resources, IAM, cost) and get an explicit "approve the apply", or have the user run `tf.sh apply plan.bin` themselves.

**AWS budget (user, 2026-10-10):** keep the monthly cap as it is for now; ask about raising it only when spending gets close. The cloud build box and sim batches share it.

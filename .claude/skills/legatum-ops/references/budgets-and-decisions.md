## Principle: question every requirement first (user, 2026-10-04)
Order of work: question, delete, simplify, accelerate, automate. Efficiently doing something that shouldn't be done at all is the first waste to remove. The supervisor missed that per-branch balance sims were unnecessary; the user caught it. Each run must name a requirement questioned and its verdict.
- **A policy change doesn't reach running tasks.** Codex prompts are frozen at start: after the per-change sims policy (12:53), the four running land-* tasks kept running ~40 400-game cohorts (~16k games, ~20 CPU-hours) plus fresh master baselines after every master move. snapshot.sh now flags prompts that ask for it; edit pending/hold at once, and tell the lead about running ones (only they can stop or accept them).
- **Audit 2026-10-04 13:10 (verdicts):** cut prose-only master reviews (28/52 that day, ~570K Sol tokens, 1 minor finding); cut repeated full suites per task (once at the end; after a master merge only determinism and pins, since the landing re-runs everything); cut per-branch scenario-baseline commits (release re-records them in ~1 min); folded ai-campaigns' separate smoke cohort into its 100-game probe; deferred the half-obsolete goal-driven proposal until step 1 lands; Laya plumbing Sol high to medium. Kept: code reviews of master (14/24 had findings), the release check (7 min warm), and the UI reviewer (user gate). Per task, `cargo test --workspace --profile release-checked` keeps overflow checks and debug assertions on while running optimized. Look next at: the 10-minute heartbeat cron in the lead session, the supervisor's own 30-minute cadence, and diff-filtering the UI tour (29% of screenshots byte-identical between releases).

## Budgets
- **Claude Max windows:** a 5-hour limit and a weekly limit for all models. Check them with `mcp__ccd_session_mgmt__get_usage`. Never use Fable (user, 2026-10-04): it burns the weekly budget faster, despite its separate-looking weekly line.
- **Concurrency:** about 12 concurrent Opus agents exhausted the 5-hour window in about 6 hours (2026-10-03, ~23:50), and every agent died mid-task. Default to at most 4–5 Claude agents. Above 60% of the 5-hour window, stop spawning; above 80%, have agents commit WIP and pause.
- **Both budgets are limited** (user, 2026-10-04): Claude (5-hour and weekly windows) and Codex/ChatGPT. Neither can grow. Pace both to their resets: move work between them by which is further ahead of its pace, and when both are tight, shift to token-free CPU and GPU work. Watch Codex for rate-limit and capacity errors in `.progress/astra.log` and the task logs; keep its concurrency at about 4 lanes, not more.
- **Pace, don't sprint (user, 2026-10-04):** spread Claude usage so the weekly window lasts until its reset. As either window nears its limit, shift to work that costs no Claude tokens: long sim cohorts, scenario baselines, release builds, profiling, plus Codex tasks. Line that work up before the limit hits, so the machine stays busy while Claude idles.
- **Weekly pace data (2026-10-04):** with about 6 Codex tasks and 1–2 Claude sessions, weekly usage grew slightly faster than the pace that lasts to the reset. That mix is the sustainable ceiling; adding Claude agents needs a matching cut.
- **Extra usage stays off** (user, 2026-10-04). Never suggest turning it on to finish a task.
- **Main session context:** near 90%, the lead writes current state to the handoff file before compaction.

## Decided and rejected (user, 2026-10-04)
- **A local open-weights LLM as a cheap tier: rejected for now.** Luna is cheap enough; it's only worth revisiting if a local model competes with Sol or Opus.
- **A big EC2 instance to finish faster: no** (partly superseded 2026-10-10, see below: offloading to relieve an overloaded Mac is now wanted, even where it doesn't make a single job faster). The critical path is sequential (Codex thinking, landing one branch at a time, the release check, the UI review). Builds are bound by the crate chain, and the laptop's cores are faster per core. Sims would speed up but are already cheap; the Mac app build and Playwright stay local; setup takes about an hour. Better levers: batch-land non-conflicting branches with one check run, and cut oversubscription.
- **Heartbeat gaps:** crons fire only while the lead session is idle, so heartbeats skip during long conversations. That's expected.
- **Protect the critical path with nice** (2026-10-04): at load ~186, the landing agent's 400-game gate cohorts took 39+ minutes instead of ~6. Renicing every Codex task process tree to 20, and leaving the landing worktree's processes at 0, gives the release-critical work the CPU without stopping anything. Children inherit nice, so renice the `codex exec` parents too. Do this whenever a landing or release is on the critical path.
- **"Merge master again before finishing" loops while landings run** (2026-10-04). land-threat re-merged master after every landing (4+ hours, nearly all re-merge and re-validation). Task prompts should say "merge master once at the end; the landing agent handles later master moves". When a task's work is committed and it is only chasing master, stop it and land the tip.
- **When Codex runs out** (2026-10-04, about 10% left): stop the queue loops and the Codex reviewer; stop running Codex tasks (their unfinished edits stay in the lane worktrees). Hand each task file (moved to `.progress/astra-queue/claude/`) to a Claude Opus agent that continues in the same worktree and branch. Claude agents can run Playwright directly, so they don't need the bridge. The user can use a Claude limit reset; keep Claude agents at about 5 or fewer.
- **No balance sims** (user, 2026-10-04): cut any balance cohort, win-rate probe or baseline measurement from task prompts as waste until the AI is competent. Functional sims only (crashes, stalls, determinism, mechanic usage, self-sabotage detectors).
- **Budget appetite** (user, 2026-10-04 evening): the user has a manual weekly reset, so don't throttle Claude work to pace the window. Keep about 5 agents running and the pipeline full; keep routing each task to the cheapest model that meets the bar.
- **Standing metrics (user, 2026-10-06; split 2026-11-21):** product performance (sim speed, AI thinking time, app size and load, CI and test time, flakiness, dead code) is measured nightly by `legatum-perf-supervisor` in its ledger. The ops check tracks turn size (pillar 3), game length, AI quality, rework and system health. The lesson stands: a new standing check is added whenever we find a cost nobody was measuring.

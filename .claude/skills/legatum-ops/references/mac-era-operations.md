# Ops: Mac-era operations (historical)

Historical: failure patterns, the Mac battery and Codex lane rules, the watchdog, standing supervisor checks and speed notes from when work ran on the designer's Mac and its Codex lanes. Since 2026-11-22 all coding happens in cloud sessions with GitHub master as the source of truth; use these only for maintainer operations on the Mac (see docs/ops/maintainer.md).

Moved verbatim from SKILL.md on 2026-11-22 (original order kept). The current rules are in SKILL.md; where this file disagrees with SKILL.md, SKILL.md wins.

## Failure patterns and preventions
- **Landing queue stalled overnight on a hung box job (2026-11-08).** balanced-starts' fixture job hung at "box: shipping a patch" from 03:41 to 09:20 when the box restarted mid-upload. The ssm proxy never timed out, the agent's waiter loop had no deadline, and the coordinator waited on that agent, so nothing landed for six hours. Prevention: `remote.sh` now has hard ssh deadlines and a stall guard (`claude/box-stall-guard`). **Every ops check now looks at the landing queue**: if master's first-parent log hasn't moved in 2 hours while a coordinator has branches queued, find the agent it is waiting on, check its last activity and its box job (`~/LegatumRuns/box/<job>/output.raw` growth, `tools/cloud/remote.sh --attach`), and report the stall to the lead with the job id.
- **Xcode auto-update breaks git and linking (2026-10-04 10:27).** Xcode 26.6 → 27.0 installed itself; its license was unaccepted, so every /usr/bin/git, cc and ld call failed. At 10:32 a newly started lane runner failed all 8 pending tasks in 6 seconds (codex -C on a lane that git could not create). Fixes: runner.sh now pauses a lane while `git rev-parse master` fails, and parks any task that fails within 2 minutes in `hold/` and pauses 5 minutes (circuit breaker). Only the user can fix the cause (`sudo xcodebuild -license accept`); the supervisor's own git can use `DEVELOPER_DIR=/Library/Developer/CommandLineTools`. snapshot.sh alerts on it. Prevention for the user: turn off automatic Xcode updates. Tasks already running when it broke recovered on their own (2026-10-04): once the fallback was on master and in learnings, they exported DEVELOPER_DIR in their shells and kept committing. Judge such tasks by commit and log age, not by license-error counts in their logs.
- **Slot pool is blind inside the Codex sandbox (2026-10-04).** Seatbelt denies signals across sandboxes, so `kill -0` on a live holder returns "Operation not permitted", the same exit code as a dead one. slot.sh then reclaims other holders' tokens, drops their tickets and breaks their mutex: the cap does nothing for Codex sims. Fix (alive() helper accepting EPERM) is folded into the build-slot task. Tasks started before f6db31a8 (09:11) also lacked ~/LegatumRuns write access: their slot.sh waiters spin in lock() forever and outlive their Codex parent (pids 9510/9512, 33037 on 2026-10-04).
- **Supervisor kills are denied** by the auto-mode classifier ("Interfere With Workloads"), even for orphans with parent pid 1. Report the PIDs and the evidence to the lead; don't retry.
- **Unresumable agents.** Agents spawned with `isolation: worktree` can't be resumed after a crash ("worktree could not be verified"). Use lead-created, locked worktrees with non-isolated agents; those resume with SendMessage.
- **Spawn failures under load.** At load around 150 or more, isolated spawns fail with "git could not be run". Fall back to lead-created worktrees.
- **Slot pool.** slot.sh now serves first-come-first-served and breaks owner-less mutexes older than a minute. If agents report hour-long waits, check the queue depth and the cap (LEGATUM_SIM_THREAD_CAP, default 12).
- **Stale worktree locks.** Locks naming a dead PID (after a reboot or crash) stop cleanup from reclaiming merged worktrees. The user approved clearing them automatically (2026-10-04): `tools/cleanup/unlock-stale-locks.sh --apply` runs every disk-watch cycle, and the supervisor may run it too. Locks without a PID (release builds, shared baselines) are left alone.
- **Disk: check free space and locked verify worktrees every run (user, 2026-10-10: "i thought the supervisor was checking that").** `verify-branch.sh` locks each `verify-<branch>` worktree with no PID and never unlocks it; `stale-worktrees.sh` and `unlock-stale-locks.sh` both skip PID-less locks, so the hourly dry run reported ~nothing while ~30 idle verify worktrees and ~650 GB (du) built up, until the user noticed 500 GB free. Every run: `df -h /` and count locked, idle `verify-*` worktrees (no process cwd inside, older than a day); report both, and flag at under 600 GB free or more than 10. The user approved removing idle ones (2026-10-10 21:23): `git worktree unlock` then `git worktree remove --force`, never one a process is using. Fix in progress on `claude/verify-speed` (unlock on exit).
- **Reboot-orphaned Codex tasks.** A reboot kills Codex tasks but leaves their files in `.progress/astra-queue/running/`, so they never restart. After a reboot, compare `running/` with live `codex exec` processes and move orphans back to `pending/` (their branches keep committed work; the runner reuses the branch).
- **Stale wasm-pkg** after a merge gives false parity failures: rebuild WASM before vitest.
- **Shared scratch files collide.** Each agent uses scratchpad/<task>/.
- **Background jobs from compound shells** (`cd … && nohup … &`) die when the shell exits. Use `nohup script & disown` at top level.
- **Hotspot conflicts.** Long-lived branches conflict in runner pins, the fixtures README, telemetry and the screen tour. Re-merge master just before landing, and land in small batches.
- **Duplicate baselines.** Every agent re-measuring master on the same seeds wasted hours. Use `tools/sim/cached-baseline.sh`, keyed by code content, with the default LEGATUM_RUNS.

- **Check ownership before requeuing or verifying (2026-10-10).** The supervisor queued `historical-faction-rename-r2` while a Claude landing agent was already fixing the same failures in `.claude/worktrees/land-rename`, and the lead had to kill it. Before any requeue, verify or landing, look for that branch checked out in `land-*` or `landing-*` worktrees (`git worktree list | grep <name>`), a `verify-*` lock in `.progress/verify/.locks/`, and the tracker row. If one exists, leave the branch to its owner and only report.
- **"Is it landed?" false positives (2026-10-10).** `git merge-base --is-ancestor astra/<name> master` reports a Codex task that has started but not yet committed as landed, because its branch still equals the master it forked from. Check that `.progress/astra-queue/running/<name>.md` is gone and that `git log master..astra/<name>` was non-empty before the merge.
- **Genes already on master (2026-10-10).** The seat-split evaluation imported held AI branches into master as default-off params. Landing such a branch is a defaults flip in `params.rs` that matches its `docs/sim-results/hard-vs-human/params/<name>.json`, not a merge, which conflicts across every AI file. Check `git diff 269b826f master -- crates/ai/src/params.rs` style overlap before merging an older AI branch.
- **Nested build-slot deadlock (2026-10-10).** `verify-branch.sh` calls `repin.sh` and `scripts/build-wasm.sh` inside `build-slot.sh`, and build-slot is not re-entrant. A script that wraps its own Cargo calls in build-slot, as `astra/timing-coverage` did, holds one slot while waiting for another, so three concurrent verifies deadlock. Review every tooling diff for `build-slot.sh` added inside a script that callers already wrap; wrap at the outermost caller only. Fixed 2026-10-10 in `claude/verify-speed`: repin.sh and build-wasm.sh take no slot themselves; verify-branch.sh and check.sh wrap at the outermost caller.
- **Never borrow a live lane's target dir (2026-10-10).** Pointing `CARGO_TARGET_DIR` at `.claude/worktrees/lane-<k>/target` for a supervisor build contends for the lane's Cargo lock and overwrites its incremental artifacts with another tree's. Use the scratchpad or an idle verify worktree's target.
- **Benchmark thread caps in task prompts (2026-10-10).** Two Luna seat-gap analyses ran `hard_vs_human` directly with all cores (about 250% CPU each, plus other work) and load hit 145, which timed out WebKit gate tests. Every task prompt that runs the benchmark must say: use `tools/sim/hard-vs-human.sh` or `RAYON_NUM_THREADS=4`. Renice offenders to +15 meanwhile.
- **Host-only work goes to the Claude queue, not Codex (2026-10-10).** The Codex sandbox blocks `sysctl` and Playwright Chromium, so `tour-cpu-profile` exited 0 with nothing measured. Codex can reach AWS (`war-cycle-measure` ran cloud batches), so sims are fine there. Never gate a task on a load cutoff: measure CPU-seconds.

## Mac battery and the Codex lanes (user, 2026-10-11)
The laptop's battery sat at 7-8% with a load near 78 on 16 cores; the user wants 50% or more. Lane commands now run on the cloud build box (see the battery rule in `legatum-workflow`): PATH shims in `tools/astra/lane-bin`, `tools/cloud/offload.sh`, `tools/cloud/box/lane-run.sh`, plus self-offloading scripts (`repin.sh`, `build-wasm.sh`) and a cloud-by-default `hard-vs-human.sh`.
- **Every run, report `uptime` and `pmset -g batt`, and attribute load from per-process CPU** (`ps -Ao pcpu,args | sort -rn | head`), not from which lanes exist. The 2026-10-11 survey found three things the shims cannot move: a Luna task running a `blunder_audit` sim binary locally (about 480% CPU), a Docker Desktop VM (about 300%) running a local `build-linux.sh` Docker build, and ordinary local `cargo build`s. Fix those at the source: put "run it in the cloud" in the task prompt, and find who set `LEGATUM_CLOUD_LOCAL_BUILD=1` or fell back to Docker.
- **Cloud unavailable means stop, not fall back to the Mac (2026-10-11).** `blunder-audit` (Luna) found the box at its daily cap and Docker's local fallback broken, so it ran its 192-game cohort locally (203 CPU-minutes at battery 7%). The same hour a lead session's `hard-vs-human.sh` ran 64 salts locally at about 330% CPU. Every sim task prompt says: if the cloud path fails, stop and report; never run `hard_vs_human`, `blunder_audit` or `legatum-sim` cohorts on the Mac.
- **Check the box is actually used:** `tools/cloud/box.sh jobs` and `~/LegatumRuns/box/*/output.log` show `lane:<worktree>:cargo test` labels. A lane whose commands show no `box:` lines is running locally: look at `~/LegatumRuns/box/offload-unavailable-until` (a fallback marker in the future means the box was unusable) and `.progress/astra-queue/no-offload`.
- **Box hours:** the box runs while any job runs and for 20 minutes after, so with 3 to 5 busy lanes plus the verifiers it stays up most of the day (546 minutes had already run by 9 am local on 2026-10-11, mostly other agents' verifies). There is no daily cap now (user, 2026-10-11); the guards are the idle stop and the monthly budget. A box that runs all day costs several times one that runs a few hours, so watch `tools/cloud/box.sh status` (runtime today) and the AWS bill every run; if the budget gets close, lower `max-lanes` or ask the user about a smaller lane box rather than moving builds back to the Mac.
- **The shim is invisible to Claude's own shells and to anything started outside `runner.sh`.** It is only on the PATH of Codex write tasks (`LEGATUM_OFFLOAD=1`). A task started before the runner reloaded keeps running locally until it ends.

## Background jobs and the watchdog (2026-10-05)
Two overnight failures went unnoticed for hours: an overnight data-generation run died in its first second on a bash error (0 decisions, nobody looked until morning), and the Claude app died around 23:18 and stayed down until 07:50. The supervisor cron only fires while the lead session is alive and idle, so it caught neither. The watchdog needs no tokens. It watches jobs only, not the Claude app: when the app is down nothing else runs, so an app-down alert isn't needed (user, 2026-10-05).
- **Launch every long background job through `tools/ops/bgjob.sh`:** `tools/ops/bgjob.sh <name> --log <file> [--ok <regex>] [--progress-min <minutes>] -- <command...>`. It registers `.progress/jobs/<name>.json` (pid, log, ok regex, stall minutes, exit code) and appends `__EXIT <code>` to the log. `--ok` is a regex that must appear in the log for a zero exit to count; make the script itself exit non-zero for failures that a regex can't express.
- **Run the watchdog as a daemon, started each session alongside pw-bridge:** `nohup tools/ops/watchdog.sh > .progress/jobs/watchdog.log 2>&1 &`. Every 5 minutes it reports FAILED (non-zero exit, ok regex missing, process vanished) and STALLED (log unchanged for the job's stall minutes) per job. Each new alert is de-duplicated (`.progress/jobs/alerted.txt`, cleared when the condition clears), appended to `.progress/alerts.log` and shown as a macOS notification. It never kills or restarts anything. `tools/ops/watchdog.sh --once` runs one pass; `--status` prints job states; `snapshot.sh` shows both plus the daemon's liveness.
- **The lead verifies a job's first unit of progress within minutes of launching it** (first decision logged, first game finished, first training step), instead of trusting the launch. The watchdog catches the failure later; this catches it in the first minute.

## Standing checks (each supervisor run)
- **Start with `tools/ops/snapshot.sh`** (read-only, ~15 s; `--sizes` adds target sizes; `SINCE=<iso>` sets the event window). It covers toolchain, usage, machine, Codex tasks and orphans, queue and lanes, astra.log failures, rate-limit greps, builds, slot pool and stuck waiters, check logs and the heartbeat. Extend it rather than adding ad hoc commands.
Budgets and burn; failures since the last run; stalled tasks (no commits for 60+ minutes while running); the slot queue; load and memory; the sccache hit rate; worktree count and dead-PID locks; stale locks in ~/LegatumRuns; release and check logs.
- **Codex usage source (2026-10-04):** use `.progress/supervisor/usage.json`, whose `written_at` is local time; flag it after 3 hours. Without a previous timestamped usage snapshot, report burn and run-out as unknown rather than extrapolating from one value. Compare the remaining weekly allowance with hours to reset to give the lead a safe average pace.
- **Process visibility in a sandbox (2026-10-04):** under a Codex sandbox `ps` and `kill -0` fail with "operation not permitted" (the Opus supervisor run can see processes). Without reliable liveness evidence, don't move running tasks or unlock process-owned locks; ask the lead to verify on the host.
- **Stalls:** snapshot's queue section prints, per running task, minutes since its branch's last commit and since its task log changed. Stalled = commit >60 and log >10; a long final check suite (e.g. `cargo test --workspace --profile release-checked`) can keep commit age near 60 while the log stays fresh, which is fine.
- **Slot cap bypass:** snapshot alerts when a sim runs under slot.sh while `slots/held` is empty (13:08 2026-10-04: 5 sims, 30 threads, 10 held). The alive() fix is on master (003fe8b6), but a task uses its own worktree's slot.sh until it merges master.
- **sccache serialised (2026-10-10):** if snapshot shows `ALERT: sccache serialised` (10+ clients waiting, the server compiling at most 1 for 30 s), every local build is stalled. Restart it from the supervisor's shell, not from cargo: `sccache --stop-server; env -u MAKEFLAGS -u CARGO_MAKEFLAGS SCCACHE_CACHE_SIZE=30G sccache --start-server`. Waiting clients compile locally (`SCCACHE_IGNORE_SERVER_IO_ERROR=1`), so in-flight builds survive. Confirm that requests climb in `sccache --show-stats`. It recurred 2 h after a clean restart, so the watchdog daemon now restarts it automatically (alerts.log line "sccache serialised ... restarted"); count those lines each run, and if they keep coming, find the cause rather than relying on restarts.
- **Runner restarts:** since 288e3f40 the queue, reviewer and reaper loops re-exec themselves between tasks when runner.sh changes (after `bash -n`). Older loops needed a one-off handoff (`~/LegatumRuns/relaunch-lane.sh <k> <loop pid> <codex pid>`: stop the loop, wait for its task to exit, start the new loop) so concurrency stays at 4. Killing runner loops by PID is allowed; it wasn't denied.

## Speed notes
- **Batch clean UI branches into one `--app` verify when load is high (2026-10-10):** build `astra/<batch>` without a worktree (`git merge-tree --write-tree` then `git commit-tree -p <prev> -p astra/<b>` per branch) and verify once; one Chromium tour instead of N. On failure, attribute by the failing test's files, then verify only the suspect branch. Only for branches that merge clean with master and each other.
- **Builds dominate load, not sims** (2026-10-04): a sim game is ~5 CPU-seconds, while each fresh worktree compiles the whole workspace in 3 profiles (~26 GB of target). Codex workers now use persistent lanes (`runner.sh queue <k>` owns `.claude/worktrees/lane-<k>`, locked; it switches branches, commits leftovers before switching, and falls back to a branch's existing worktree). Don't run several agents in one worktree at once: cargo's build-folder lock serializes them, half-done edits break each other's builds, and mixed AI changes confound sim measurements and tape pins.
- Testing runner changes: a self-test of `prepare_lane` against an existing branch merged master into a live task's worktree (harmless, docs-only). Test only on throwaway branches and lanes.
- `player_view` was 52% of sim CPU; fixed 2026-10-03 (about 1.44x). AI PlayerView clones are about 8% next (Astra task perf-playerview-arc-tiles).
- sccache shares registry dependencies, not workspace crates, across worktrees (about 35–40% hits).
- **Build contention observed (2026-10-04):** load 54 on 16 logical cores while several branch integrations remain and individual worktree targets reach 13–26 GB. The queued `build-slot` task is the direct mitigation; the runner takes the oldest pending file first, and this task was oldest at inspection. Let it run at the next free worker before adding more heavy checks. Use load as a contention warning, not as proof of which process caused it.

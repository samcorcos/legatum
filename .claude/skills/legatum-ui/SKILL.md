# Legatum UI preferences

Pillars 5 (no hidden math) and 9 (the next action is always obvious) from CLAUDE.md govern everything here.


This file holds the current rules, one line each. The user's words, dates, as-built notes and review findings are in `references/` (index at the bottom); search them before proposing UI that might already be decided.

## Sizes and verification

- The user's laptop window is about 1000x600 CSS pixels: the primary desktop size, not an edge case. Verify at 1000x600 and 1440x900 (and phone width for layout changes) with headless Playwright screenshots, never the app's browser pane.
- The game is tuned for Chrome and browsers built on it (user, 2026-11-25: "we only need to solve this for chrome, and we should tell people using other browsers that this is optimized for chrome"). Other browsers see a quiet title-screen footer line, "Runs best in Chrome" ("...on a computer" on an iPhone or iPad), from `platform/browser.ts`. No dialog, no blocking, nothing recorded. The note stays on the version line's row at desktop widths; both footer lines are `nowrap`, and on a narrower screen the note takes its own row rather than wrapping mid-phrase (UI review, PR 199). A screenshot of it in Chromium must remove `navigator.userAgentData` as well as set the user agent.
- No picture trickles in (2026-11-26): a screen is complete the moment it opens. Small pictures a screen will show are fetched in the background once a game is on screen (`app/src/artWarm.ts`), and a picture's file is about twice its largest drawn size, not the full painting (a 34 px thumbnail uses the 64 px file; round portraits offer a 112 px file beside the 360 px one). A new screen or picture family gets a row in `tools/perf/first-open.cjs`, and a swap to a smaller file is compared before and after at pixel ratio 2 on its largest use.
- Every new screen or decision card joins the screen tour (`app/e2e/tour/`) with a fixture in the same change. Fixtures use shipping names and states the rules can produce; park the mouse before shots.
- Test layouts with two humans as well as one; test controls with their longest label.
- A wording change that makes a word longer is checked in the narrowest place it shows: the 1000x600 right sidebar while a unit is selected (about 170px wide), not only the default tour shots (UI review, PR 170: "health" made the siege card's loss text overlap its number there). A row with a big number and a status wraps instead of squeezing: flex-wrap with `white-space: nowrap` on each part, never a `minmax(0, 1fr)` / `auto` grid.
- A rewrite that drops an established interaction (click targets, shortcuts) is a regression: list a screen's interactions before rewriting it (user, 2026-10-11).
- Review a moving checkout from a clean worktree of the commit under review: a shared working tree with uncommitted edits shows screens that no commit has (UI review, PR 212).
- Never override a stated user preference for a general guideline; satisfy both or ask (user, 2026-10-17).
- Question every requirement on every screen: review each screen and map piece for what can be removed or merged without losing a decision, and before each release check one icon, word, colour and component per concept (user, 2026-11-22). Art quality belongs to `legatum-art-reviewer`.

## The next action is always obvious (pillar 9)

- A goal that a unit or a place can score says who can score it (the unit is announced and marked the turn it qualifies), where (the view already used for that action marks the places and its button names the reward), and tells rivals (the same mark on the map with its VP, a public card, a line in the capture forecast); one mark per goal (user, 2026-11-22, Colonia Victrix and the Royal Tomb; `references/feedback-rules-2.md`).
- Goal marks and recommendations (UI review of the Colonia Victrix and Royal Tomb, 2026-11-22; reviewer's rules, accepted by the lead): a lens that recommends places ranks by the goal the selected unit can score there, never pointing away from the marked scoring sites, and its legend names the unit actually selected; a rule that stops a city from building replaces the banner's "Build" prompt with that rule's mark and count; a public card about a goal wears the goal's engraved reward emblem once one exists (the Royal Tomb's `emblem-tomb`, 2026-11-25), otherwise the goal's mark, with the empire's crest as the corner badge, and the report line for the same moment wears the same emblem; banner seals, goal rows and progress lines keep the goal mark; every map mark is checked at far zoom beside the capital star, and a thin-line glyph gets a solid far variant; the compact 1000x600 goal row keeps the goal's name or action and its "+N VP" (progress may move to hover, the reward may not); top-bar compaction never drops Gold income before a faction readout has gone to its short form; a gilt-ringed seal on a city banner means "holding this city scores VP" (capital star, laurel, tomb), dashed for not yet standing, solid for held; when a goal's condition names a unit class ("melee veteran"), every short form keeps the class.
- Goal offers and goal rows (second UI review of the Colonia Victrix and Royal Tomb, 2026-11-22; reviewer's rules, accepted by the lead): a dock offer or primary names what Return does (if it only selects a unit it says "Select…" and steps back once that unit is selected), and an offer for a goal that cannot be done yet says what is missing, never the goal's verb; two lines on one screen never disagree about the same state; a goal that is done or lost has no action button, only one line (name, +N VP, who holds it, where) and Show on map, and a lost row names the holder and the next step; every public surface about a rival's goal states the VP as a number; a planned-site mark stays while progress is kept (a pause changes its words, not its presence); a rule that stops a city working is said once per panel and build buttons read "Queue" while it holds. Text: say "it happens when the turn ends", never "resolved"; the screen is "the Victory race (G)".
- Goal lines by state (third UI review of the two goals, 2026-11-22, verdict ship; reviewer's rules, accepted by the lead): a hover or card line with a branch per state (working, paused, standing; own, rival) states the reward in every rival-facing branch, and each branch has a test; a goal button's label fits two lines in the narrow 1000x600 sidebar with the unit panel open, and a longer one gets a short form that keeps the verb and "+N VP"; a goal row whose button is not the scoring act (Pause) carries a quiet line with progress and "+N VP"; when a unit card's primary names the goal and its reward, the card does not repeat it in a status line above; a public-event card's headline is at most two sentences, with the rest in its details (plain-language review). Owed minors from that review: short "Resume tomb · +2 VP" label, a progress line on the working row at 1000x600, "Growth paused" wording in the city panel, the unit-card line dropped while the Found button is live.
- One unmistakable primary action per screen, visible at 1000x600 in every seat setup; anything clickable looks clickable before hover; one live Return primary at a time.
- Public names and refusals (UI review of the public game list, 2026-11-25; reviewer's rules, accepted by the lead): a public name the server makes from an id (the online game list's "Amber Harbour 07") is shown on every surface where the host might pass it on (the game room, the in-game menu and the Online chip's tip), not only the first screen; an identifier players read aloud or match by eye uses lining figures (`font-variant-numeric: lining-nums`); a refusal's button sub-line never repeats the notice's own sentence. "Your network" (a wider group of nearby addresses) and "your internet connection" (one address) are different scopes: keep both, never merge them.
- Keyboard first: Return confirms or advances, Esc closes; Escape never throws away something he has to answer, and the turn report (L) brings back whatever it hides (user, 2026-11-21).
- Invalid choices are greyed out with the reason next to them, in one line, where the price would be; never accept an order that will fail (offer "Declare war on X?" instead); a broken order is the next decision ("Fix order").
- A unit line in the production list leads with the most advanced unit the city can build now (user, 2026-11-25: a new player had the tech but no Iron, saw only the blocked unit and never found the Spearman under "Also"). A newer unit short of its strategic resource sits one line beneath it ("Pikeman needs Iron", Iron opens the supply, + Queue once something is queued), as the AI builds (`composition::best_buildable_in_line`). The advisor's ring on a folded unit points at its "Also" summary first. An item queued while it can't start says why in its queue row ("needs Iron"), never a turn count; a tooltip is the core's reason plus at most the item's description, and what a button does goes in its own title (UI and plain-language reviews of PR #155).
- The same holds for unit upgrades (UI review, 2026-11-26): the Improve row offers the most advanced unit the empire can supply, and a newer unit skipped for its resource gets one quiet line beneath ("Musketman needs Niter", the resource opening its supply), not only a sentence in the explanation.
- A card held until the player acts closes only by its own controls; acting on a decision card closes it; a card that announces a finished mechanic offers the next idle decision as a button.
- A background failure (upload, save, network) is a small corner notice, never a card over a decision (2026-11-07).
- A held card's call to action follows live state when it shows, not the state when it was planned (PR #32, 2026-11-22).
- Every new Age opens a score check for every player (user, 2026-11-22; `celebrate/ScoreCheck.tsx`): the VP track plus your sheet of ways to score, fitting 1000x600 whole; any VP you have is a filled box, held vs kept a second mark; a "how to score" line names the action; each box draws the thing that scores (Age numeral, capital star, wonder or goal icon). Premium is the default when Sam leaves polish to judgment ("use your judgment. remember that the game needs to feel premium", 2026-11-22): it tallies on opening (crests hop up the track, your boxes stamp in, ~2 s, skippable, none under reduced motion). A legend line for a state shared by several kinds of box must be true for all of them. Detail: `references/review-findings-2026-11.md`.
- The hosted title screen (uploads on) has about 10px to spare at 1000x600: the upload notice stays 2 lines; any further hosted-only line needs a layout change. Shoot it separately from the standard tour build, which has uploads off (PR #33, 2026-11-22).
- The advisor is on by default, explains the Hard plan from the seat's own view without acting for the player, and shows one card and one gilt ring at a time (`e2e/tour/first-run-advisor.spec.ts`). A floating advisor card never covers its target, the selection, a dialog's primary or the options' names, and moves clear of the map tools and your own cities when there is room (`ui/Advisor.tsx`); inside a dialog it is a one-line strip, and the ring marks only a control in that dialog (anything behind it can't be clicked). Once research is chosen this turn with the Research panel still open, the advisor's next step is "Close Research" with the ring on Close (not when you open Research later just to browse; Not now dismisses it) (`ui/advisorModel.ts::advisorSuggestion`, `ui/Advisor.tsx::targetElement`). The card is headed by your people's seal, with no "Advisor" eyebrow word. A target control that is off screen is scrolled to the centre. Looping animations honour the Animations switch. Routine pointers fade out with practice (user's co-op partner, 2026-11-25: "it doesn't need to show me where to move my unit every time", only new things): moving a unit, Fortify or Wait, Skip, Auto-explore, End turn and Close Research stop showing once this player has done each on 3 different turns (`PRACTICE_TURNS`, counted per browser so each online player has their own); builds, research, Settler moves, Found City, attacks and the one-time lessons always show. Settings has Show every step again (`ui/advisorModel.ts::practiceKind`). Situational tips (user's co-op partner, 2026-11-25: advice like "build up your army or you might get attacked", "build a city to get iron", "buy a tile to get iron", with a reason, never repetitive): `ui/advisorTips.ts::strategyTip` shows one card, before routine decisions and never over a unit or panel in hand, for a close rival whose team has at least 1.5x your team's army points (and 10 more; team totals: living teammates' army points added up, `ui/advisorTips.ts::armyTip`), a revealed strategic resource you lack (buy the tile if a city can afford it now, else found a city by it), or 250+ Gold (never for Switzerland, whose Gold earns interest). An enemy army at a city is This Turn's alarm ("Army closing on ..."), not a tip: a tip never repeats a warning already on screen (UI review, PR 162). Rationing: one tip at a time, 4 turns between tips, a cooldown per kind (army 25, resource 20, Gold 20 turns) that doubles with each repeat, and only while the situation holds. A tip with a ring is dismissed by a quiet Not now (the ring is the call to action); one without a target keeps a primary Got it. A tip that starts a mode keeps guiding inside it: the buy-tile tip's last step rings the exact tile while Buy a tile placement is open, and no other card shows then. A tip quotes numbers under the name the game uses ("army points", as the post-game report). A tip that names an improvement must be true for every resource it can fire on (Oil, Niter and Silicon don't use a Mine), so it says "improve it" (plain-language review, PR 162). A control that resets or clears something confirms in place what it did, rather than just disappearing (UI review, PR 152).
- A G17 decision notice is never covered by a dialog that opens from the same click: a build that replaces the current one does not advance to the next decision (2026-11-22, UI review of PR #78).
- A choice that throws away progress says what is lost in words ("Turns 4 to 6 are played again"), and its selection is shown in ink, not red (2026-11-22).
- Anything added to the title screen is checked at 1000x600 in both the standard and the hosted build; an action that shows only sometimes is one line with no sub-line (2026-11-22).
- The title footer is one line tall, a fixed budget: build facts share the version's row ("Version … · web … · Last updated …"). A second footer line ran into the online Multiplayer menu (Resume, a notice and the name note) at 1000x600; anything that adds height to the footer or that menu must pass `e2e/tour/online` on a relay build at 1000x600 and 1440x900 (UI review of PR #104, 2026-11-22).
- One entry per game on the title menu (user, 2026-11-23: "what's the difference between resume and continue?"): when the newest autosave is the game still open, only Resume shows; Continue appears only with no game open or for a different saved game. Menu entries name the game by its people ("Rome · Turn 51"), never "Player 1"; a sub-line names at most two peoples then "+N" and leaves out seconds, so it fits one line at 1000x600 with 8 seats. Carrying on a game has one slot: the top of the menu, as Resume or as the primary Continue (UI review of PR #119).
- Never a blank page: a boot plate before React mounts, and one full-screen crash card with Reload as the primary (`ui/CrashScreen.tsx`). Saves never fail silently: a failed write shows one notice whose action is Save to file; replacing a saved game asks once with focus on the safe choice (2026-11-22). The in-game Menu offers Load an earlier turn for a local game (the last 10 autosaved turns, `ui/EarlierTurnDialog.tsx`; never in an online game; not on the title screen, which has no room for it at 1000x600). The dialog says which turns are played again and that what was done in them is lost; the chosen turn is marked in ink, and a Buy or a replaced city build names the city and offers Undo through the G17 notice (`CityPanel.tsx`), because a misclick before End Turn is easy to miss (Sam, 2026-11-22).
- A confirm dialog opens on the safe choice and Esc means the safe choice; a dialog Esc closes also shows a visible close control; a button's label says what the click does (2026-11-22 reviews). A turn-failure dialog (`TurnFailureDialog`) follows that: the X sits top-right with `title="Close (Esc)"`, its destructive button says "End the turn with my orders cleared", and a status note ("Saved.") clears when the dialog reopens for the next state (PR #30 review, 2026-11-22).
- A refusal from the game server is a short plain notice with one next step, never "relay", "socket" or a code; offer a retry only when it can work (relay review, 2026-11-22).
- Online hosting admin (join-code review, 2026-11-22): an optional host setting sits beside the name box, not under it, so the Multiplayer menu keeps its height at 1000x600; a locked game shows a lock mark and the word "Locked" in the list; a guest types the join code once, inline on the seat screen, and the seat buttons wait for it with the reason beside them. Remove (host only, destructive) asks inline ("Remove <name>?" with Keep focused, Esc keeps) and never uses `window.confirm`; the seat then stays closed until the host presses Open seat. A rare admin action never forces a fold open: in a game, Remove waits behind Turn details, and at 1000x600 the race panel and the primary action stay whole with the host's default sidebar. An inline confirm scrolls itself fully into view. A field's error replaces its hint; it is never a toast above that moves the buttons. A refused join code follows this (2026-11-25): the code box turns red and tinted, with an alert mark and "Wrong code. Check it with the host and try again.", and the box takes focus; no second notice above the seats. A field that autofocuses has a calm ink focus ring, never the accent red, so its error state is the only red one; a hint that can become an error keeps the same height in both states, so nothing below it moves (UI review, 2026-11-25). Player text never says "relay", "socket", "token" or "connection".
- **Team map pings (2026-11-22, `claude/review-team-pings`):** the control is a quiet "Ping" strip at the foot of the right sidebar (`ui/PingControl.tsx`), shown only with a human teammate (never in solo, never on a host that does not relay pings), plus the P key and "Ping this tile" in the touch tile card. Do not hang it on the minimap (hidden at 1000x600 with a unit selected) or the hover tile card (not clickable). The map ring (`map/pingDraw.ts`) pulses once for a new viewer, then stays still; it adds no per-frame work when no ping is live. Guide text says "VP", sentences at most 30 words.
- **Deals (rules 61, 2026-11-25; UI review of PR 184):** Gold in an offer is one field per empire above its offers, never one per button, and its forecast names who pays, when, and the treasury it comes from ("You pay 40 Gold when they accept. You have 120 Gold."); an amount you can't pay disables the offers with the reason in place. An offer that carries Gold says it in the headline ("Sparta asks 40 Gold for Peace"). A second treaty state (Open Borders) goes under the empire's name, not in the row's badge line, which has no room at 1000x600 (the name truncated in the first tour). Every Gold forecast counts the Gold queued orders already promise (gifts, offers you pay for, accepting an offer that asks you for Gold), never the bare treasury. A panel has one "queued + Undo" pattern (the button stays pressed, a "Queued: … Undo" sentence under it) and one amount-entry component (`GoldStepper`). Friendly actions are grouped and come first; the hostile one (Declare War) comes last, below a rule. Tour: `e2e/tour/deals.spec.ts`. Polish from live play (2026-11-25): Diplomacy hides empires not met exactly as the rivals table does, collapsed into one "N empires not met yet" line (never a row per unknown empire: it would only repeat "Unknown" with nothing to do); a blocked action always says why in place, in the player's terms ("Waiting for Athens’ answer to your Open Borders offer, due turn 6.", never core's "outstanding proposal"), where the offers would stand; an outcome that only reached the turn report (an offer rejected or lapsed) also stays on that empire's row for a few turns; a button that would replace a queued order (one diplomatic order per empire per turn) says so under it ("Replaces your Open Borders offer"); a treaty taking effect is a moment card (both crests either side of the treaty emblem, the deal Gold), never a takeover: the small card for Peace and Open Borders, the framed major card for an Alliance. UI review of PR 194: every Gold delta shown during a moment, on the card and on the HUD counter tick, is coloured from the viewer's side (green + for a gain, red − for a cost); a treaty moment states every ongoing cost that starts with it (the Alliance upkeep); a moment card's kicker never restates its title.
- A new order kind goes into `ORDER_KINDS` (`app/src/orderDecoding.ts`) in the same change, with a tour shot of the pending-orders line (PR 31 review, 2026-11-22).
- Online: an action that ends a shared game says so and asks first, with the label branching on host or guest; status text is written from the viewer's role; durability text matches the storage behind it (no "saved" for a tab-lifetime copy) (co-op review, 2026-11-22).
- **Rivals table, Civ 6 style (user, 2026-11-25: "in civ, i always turned on the setting that puts the other civs in the top right ... we don't have that here"; the old standing block and "All empires" fold "always felt off").** The Victory race opens with an always-open table, one row per living team ranked by VP: VP of the target, Peace or War in words with its emblem, then Gold, Army, Cities, Science per turn (Science replaced Era on request). Yours is gilt-outlined; a met rival's row is a button into Diplomacy. An army at least 1.5 times yours is red. An empire you haven't met is "Unknown" with only its VP and "Not met yet": no name, crest, treaty or numbers (user: "unmet are hidden"), unless you are at War with it or have declared War on it. Public chips (closed country, tomb work, lead, decadence, a fallen capital) take their own line under the row, so they never run into the numbers. The way-to-score tokens and their hover cards are gone from the sidebar; the Score ledger holds them (`ui/RivalsTable.tsx`). Column heads are the yield and army icons (words in the hover); the army number is "army points", the game's one name for it. A met rival's row ends in a quiet `›` so it reads as clickable before hover; on screens under 700 px tall, Peace (the default) goes unsaid and only War and Alliance show, so most rows take one line. A row shows at most two portraits: a team of three or more shows its first portrait and a "+N" roundel (hover names the empires), and the name column keeps a short word's width so a squeeze wraps between words, never one letter a line (`RivalsTable.tsx::MAX_CRESTS`, 2026-11-25).
- **Unmet empires stay hidden on every screen (2026-11-26):** one check, `unmetTeam` in `app/src/empires.ts` (not met, and not at War with you), and the score model (`buildVpModel`) already names such an empire "Unknown empire" (its row "Unknown") and flags it `unmet`. A screen that draws an empire's crest, portrait, goal, Gold or AI level checks `unmet` and shows the dashed "?" disc (`EmpireCrest` in `vpParts`) instead; only its VP and rank stay public. The Score ledger column reads "Unknown · Not met yet" with dashes in every cell, and its detail lists leave unmet empires out with one "N empires not met yet" line; the Age score check says "Unknown empire". In a sentence (event cards, the turn report, the near-win warning, Share the Learning) it is "an unknown empire", as in Civ, and a card about it wears the "?" (`Moment.unknown`), never its crest or portrait. Words: "Unknown empire" / "an unknown empire" in text, "Unknown" in a tight label, "Not met yet" for its status. A hidden empire also loses its colours: anything that paints with `--oi`/`--pc` needs a muted fallback (the ledger's VP boxes went blank without one). Every headline, portrait, alarm and report line about another empire goes through `unmetTeam` (the turn report's `contextFromViews` already does), not only the score model; the near-win and hold alarms show the "?" disc, no motto, and no repeat of the headline. In the ledger a hidden cell is the column head's dashed "?" disc, smaller, in ink-2 (`sl-unknown-cell`); "—" means none scored.
- **Narrow tables (UI review, 2026-11-25).** Size each cell against the largest realistic value (five-digit Gold, four-digit army, three-digit Science); numbers group thousands ("1,396") and shorten from 10,000 ("23k") with the exact figure on hover. An empire's name is never ellipsized: it wraps, because " · AI 2" is what tells twin rows apart, and non-breaking spaces keep "AI 2" together. Narrow number columns keep a 5 px gap on taller screens so neighbours never read as one figure (3 px under 700 px tall, where the name column needs the room); any spacing change in the sidebar is checked against "Switzerland" at 1000x600, and a single-word name never breaks mid-word, and hovers show the exact grouped figure. Check a short-screen collapse in the full sidebar at 1000x600, not only the slim rail. A status chip inside a button row must not look like a button. A hook that counts rows hidden below a scroll edge re-measures on content change too, since a `display: contents` wrapper never fires a ResizeObserver. A tour shot meant to show a rival's state stages first contact with it first.
- Big moments get a full interstitial: war declared on you, entering an era, the end of the game; a rival closing on victory and a city under attack are never a surprise (user, 2026-10-08, 2026-11-11).
- Meeting another empire for the first time is a big moment (Sam's co-op partner, 2026-11-25: "like in Civ, an unwrapping"; `celebrate/MeetingTakeover.tsx`): a held full-screen plate per empire met (their crest as a wax seal that breaks, the letter unrolls, ~2.4 s, none under reduced motion), their portrait, a greeting in their own language with its meaning (only attested words, `celebrate/greetings.ts`), their sheet's strengths and prices turned to the third person (`asTheirs`, never a second wording), how to face them, where you stand and where they are; their people's music plays while it is up. Continue is the one primary; Show on map and Diplomacy are quiet. It follows the era-up and score check and is never folded into "+N more". A plate naming two peoples describes both: each column gives each people its own labelled rows (UI review of PR 184).
- A people's text reused outside its own sheet must stand alone (UI review of PR 153, 2026-11-25): a row the sheet shows on a piece's card (`onCard`, "Iron Working unlocks it") is named or left out elsewhere; text shown to a rival drops advice meant for that people's own player as well as turning "you" to the third person; a tour shot taken after a faked event also fakes the state that event changes; a seal or medallion animation is checked frame by frame for a square edge, and a CSS `animation` shorthand without a name is written out in full (the minifier turns it into `animation: none`).
- A menu action that can fail shows its busy and failed state on the control the player pressed, never on a neighbour. A flow that resumes a shared game says who still has to come back, and how.
- A notice never sends the player down another path by hand: when the way forward is elsewhere ("host it online"), the game takes them there with what they already chose, and that path is the primary action. Nobody picks a file twice. A button that cannot act for this save is disabled, with its reason, before it is pressed. Disabled title items are dimmed by their ink, because the menu's rise animation overrides opacity. Removing a mode includes a migration check: a save made in that mode lands on one clear next action from every entry point (Load Game, Continue, links), with a tour shot of each (hot-seat removal UI review, 2026-11-25).
- A disabled reason is said once on a screen, under the item it belongs to; other items blocked by it say only what is different about them. A host or continue action names the game it acts on (peoples or players · turn). A tour shot of a map piece centres on that piece, not on its city (UI review of the save host flow and Royal Tomb, 2026-11-25).

## No hidden math (pillar 5)

- Every number has a breakdown on hover or click; hover is for reading, click opens breakdowns; a hoverable bubble never covers its trigger.
- A number shown is the number in force, and a limit that applies is named in the same line (user, 2026-10-17). Label gross versus net; each number once per card; one source per number.
- Forecast headlines include every consequence (walled-city fire, Siege); a line that changes a number shows both numbers.
- A forecast opens with the outcome in words a first-time player understands ("Both units survive", "You will likely destroy the Archer", "Your Horseman could be destroyed") and who takes more damage, with both numbers; the odds, strength tables and notes come after. No bare verdict word ("Risky") and no row of 0% / 0% (user, 2026-11-25: a first-time player could not read the old card). A bonus always says what it adds to ("+6 strength"), never a bare number (plain-language review, PR 157). The title's colour follows its own claim (green: the target dies or the city falls; red: your unit may die; ink otherwise); the damage trade colours the detail line with a ▲/▼ sign. Outcome words use fixed thresholds on both sides: 100% "will", 60%+ "will likely", 40%+ "good chance", 20%+ "some chance", below that "small chance". A loss headline never sits beside an average health figure that implies survival. No 0% / 0% row on any forecast surface (card, touch summary, Keshig card) (UI review, PR 157). Health is said in words, never colour alone: each side reads "Health 100 → 63" with "−37 health" in red under it, and a likely loss reads "→ lost" (user, 2026-11-25: a new player read neither the bar colours nor "HP"). On touch, Confirm stays pinned in view while the card scrolls.
- When an era-scaled number makes a fixed figure wrong, show the number computed for this city and era ("+6 city strength for the next level"), never a vague word like "more" (UI review of PR 137, 2026-11-25). Compute the item's card text the same way, or a tooltip that joins the two shows both versions (PR 159).
- Costs are loud (red), including ongoing upkeep on every build card; neutral "nothing yet" lines are muted ink, never green; colour is from the viewer's side.
- A forecast line for a cost that applies only on an outcome (capture, founding) names the condition ("If you take it: …"), like the VP line's "while you hold". A new line on a production card goes inside the card's own rows (for example the upkeep row), never as a sibling of `.production-choice`, which is a two-column grid (2026-11-26, city upkeep forecast).

## Game text: plain language

Every word a player reads (sheets, cards, the Guide, tooltips, breakdowns, report lines, refusals) follows this guide (user, 2026-10-17: "'per complete pair' is not normal language... is there a rule... to make sure we use normal language"). The cause of the bad wording was agents translating code literally (`floor(pop / 2)` became "per complete pair"). Write what the player gets, not how the code computes it.

- A threshold rule ("up to N are free, past that ...") must say what happens to the first N once you pass N. Check the wording against the formula at N+1: city upkeep charges all 7 cities at 7, so "your first 6 cities are free" was wrong (plain-language review, 2026-11-26).
- When a rule adds a new part to a total (upkeep, income), grep every note that lists that total's parts and update it; a cost shows the same sign and colour in every breakdown that lists it; a new ongoing cost from founding or capturing a city is forecast where the player makes that choice (UI review, 2026-11-26).

- A report line for an order that failed ends with what the unit does next turn or what the player should do; its details never just restate the headline's rule. A new Guide rule gets its own paragraph when the existing one already holds more than two rules or about 80 words (UI review of PR #58, 2026-11-22).
- **An empire is named by its faction everywhere, never by its seat name (user, 2026-11-22: the race panel said "AI 2" where the ledger said "Sparta").** Text names a rival with `empireOfPlayer` / `empireNameOf` ("Sparta", or "Sparta · AI 2" only when two teams play the same faction); seat names belong in the lobby and the who-are-we-waiting-on line. A human teammate's own name in "Commanded by …" or "Managed by …" stays a seat name. Reviewers grep player-facing text for `.name` on player objects.
- **A report line about someone else's unit never says "you" or "your" for them (UI review of PR #73, 2026-11-22).** Core reason strings are written for the unit's owner ("took the city with force 40 against your 30"). For a rival's or teammate's unit, the formatter names the owner's empire instead, and advice such as "give it a new route" goes only on the player's own units. Every such formatter has a test for a unit the player doesn't own.

- **No rules nuance on a headline (user, 2026-11-23, Byzantium's "Thin levies" card: "this should just say 'you can field at most one military unit per city, plus one more'; all the other stuff is rules nuance that we don't need in the explainer"):** what counts and what doesn't, what happens when a city is lost, once-per limits and comparisons with other empires go to the Guide. A faction sheet row keeps its fine print in `strengthDetail`/`priceDetail`, which the Guide prints instead of the headline. `app/src/ui/explainerLength.test.ts` fails a sheet row, unit, building or technology card, or class note over 25 words, and a sheet row over two sentences; the reviewer aims for about 15.
- **A card's blurb adds what its summary and header don't (UI review of PR #118, 2026-11-23):** never repeat a number or resource the card header shows (moves, Oil or Iron use, cost); if a shortened blurb only restates the summary line, show the summary alone. A class note is shared by the whole class, so it never states a number that differs within it (the War Elephant and Early Tank have 3 moves, horses 4).
- **Tone:** a good board-game rulebook, or Civ's Civilopedia at its clearest. Plain, warm, exact.
- **A treaty's one-line definition is at most two sentences (plain-language review of PR 184):** what it does and how it ends ("Your units may enter each other’s land. Either side can close the borders for free."); what it does not do, Gold terms and edge cases go in the Guide, and a help paragraph shows only the definition.
- **The card says the rule; the Guide says the fine print (user, 2026-11-21, on the Celts sheet line "Barbarians never attack the Celts, all game. No camp, scout or raider touches your units, cities or Settlers, and the warband camps you raise raid your rivals only."):** "a typical board game ... would tell you the simple explanation and then in the rules, there would be a much more detailed explanation in the rule book. e.g. this one might say 'Barbarians don't attack the Celts' and that's about it. Then all the nuance of other things (can i attack them? can i take camps? when i attack them, does it still do damage?) get handled in the rule book." A sheet row, card, tooltip, tip, notice or report line is one short sentence (about 15 words, two at most) that a player can act on. Exceptions, what it doesn't cover, interactions and edge cases go in the Guide (`GuideContent.tsx`; a faction sheet row's longer `detail` is what the Guide prints). Drop emphasis that adds no rule ("all game", "always"). The headline must still be true: for every faction that sees it ("up to level 5" is false for Sparta), in every era it applies to (Mongols build Walls from the Medieval era), and everywhere a shared string is reused (a unit's rule on a tech card must still name the unit). `legatum-plain-language-reviewer` checks this on every PR that changes player text.
- **A card's way to the rulebook (UI review, 2026-11-21):** a faction sheet ends with "Full rules in How to Play", which opens the Guide at that faction's own rules. A link-style button is at least 13px in the accent colour with a `:focus-visible` ring, so it reads as clickable before hover. A deep link into a modal scrolls only the modal's content pane, never the dialog shell: the title and Close stay in view.
- **A number the player can change is never stated as fixed (user, 2026-11-22, on the title screen's "You against five AI empires": "it could be more or less than that"):** say the range ("1 to 7 AI empires", built from the constants) or show the live count; "five" is only true as "five by default".
- **Numbers first, in the player's terms:** "+1 Gold for every 2 population", not "per complete pair of population". "Up to 100 health", not "(max 100)". "At least 1 move", not "(minimum 1)".
- **Rates side by side use one form (plain-language review, 2026-11-22):** two or more rates in a sentence are all percentages or all words, in the same order as the things they rate: "turn 50% and 25% of a city's Production into Gold and Science. Other empires get 25% and 10%", never "half and a quarter … a quarter and 10%".
- **No mechanics-speak or code terms,** unless the game teaches the word: floor, rounded down, complete, held (for Gold: say "in your treasury"), accrue, tick, live or permanent VP source, base (strength, cost), adjusted, multiplier, stage, view, excepted, retain, provided that, mutually exclusive, Σ, max/min, i.e./e.g. A rounding rule is never worth a clause: state the number or say "about".
- **In-theme words for mechanics:** interest (Swiss Gold from the treasury), tribute (bought peace), levy (Byzantine armies), the agoge, a vow (Sakoku). Lore may be colourful; rules lines are plain.
- **Every rule fits one plain sentence** (user, `legatum-design`). If a rule needs a paragraph of exceptions to say, flag it as a design smell rather than writing the paragraph.
- **One idea per sentence,** at most about 30 words, no more than one semicolon. Active voice, second person ("you", "your cities"). No stacked qualifiers ("each military unit beyond your first two, Scouts excepted, per turn"): split them into sentences.
- **Say what it means for the player and when it matters,** not how it is implemented. "Your units deal half damage to city health", not "half damage, rounded down after the attack roll and any siege bonus".
- **A live goal says how it is lost** in a sentence: "You lose the VP while your treasury is below 1,000 Gold", never a "Live:" tag.
- **Text shown for another empire is third person** ("its land"), and shared rule text built by one function never says "you" for a rival.
- **The same term everywhere** for the same thing. The glossary below is canonical; its synonyms are lint failures.
- **A drawback sits beside the ability it pays for** (user, 2026-10-17, Germany's sheet: unrelated rows side by side read as related). A faction sheet row pairs a strength with the price that offsets it; a strength with no matching price stands alone across the row (`FactionPair.price` is optional). A "drawback" that only restates its ability is not a drawback: cut it.
- **A faction sheet row is the rule, not its fine print (user, 2026-11-05, Swiss sheet: "i think we can simplify this"):** one idea per card ("Only Switzerland can buy a world wonder" (superseded 2026-11-06: Swiss wonder buying is cut and nobody buys wonders); "Military unit upkeep is triple: 3 Gold a turn instead of 1"). Leave out exemptions every empire shares (Scouts pay no upkeep for anyone), consequences the player can work out ("can finish a contested wonder immediately", "can delay the reserve goal"), and one example item's price standing in for a class (a Great Library price when every era has its own wonder). Two unrelated drawbacks are two cards, not one paragraph.
- **Compare a replacement with what it replaces in the same breath:** "Ruhr Foundry: +6 Production (a Forge gives +3)", never a bare "+3" that leaves the player asking whether it is on top.
- **No standing explainer notes** that restate what each line already says (a "A live goal gives VP only while..." note under goals that each say how they are lost). Say it once, where it applies.
- **Every form of a template reads well:** check the one-item and many-item forms ("moved 1 tile, now 1 tile E of Kyoto" as well as "moved 3 tiles, now ..."), the at-Peace and at-War forms, and your own and a rival's.
- **A note under a breakdown uses the breakdown's own split** (a growth note saying "30 + 16 per population" over a table of "Population growth + Game pace" is two stories).

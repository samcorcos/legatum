# Rule experiments

Part of the Legatum rules reference (index: `index.md`). Answers: Which simulator-only rule experiments exist (research cost, faction-rule ablation) and how are they switched on?
Moved verbatim from `game-rules.md` on 2026-11-22, in the original order; the original section headings are kept inside.

**Research-cost experiment (off by default):** simulator-only `--rules-experiment tech-cost-percent=N`
sets research costs to N% after diffusion and optional city-research adjustments. Valid values are 1–100; unset preserves ordinary costs. See
`crates/core/src/experiments.rs::RuleExperiments::tech_cost_percent` and `economy.rs::tech_cost`.


**Faction-rule ablation (off by default; designer, 2026-11-05):** `RuleExperiments::faction_rules_off` (`experiments.rs`; `legatum-sim --rule-off germany_ruhr_production,germany_ruhr_food,germany_double_supply`) switches individual faction strengths, drawbacks and goals off, so a census can test that each one moves its faction's win share (a strength switched off should lower it, a drawback switched off should raise it). `FactionRule` has one variant per active rule (60 across eleven factions, 2026-11-21: names are snake_case, the faction first, `swiss_` for Switzerland; each faction's last rule is its goal except Egypt and Rome, which have no goal in increment 1, and Egypt's `egypt_nile` (rules 48) switches the Nile off for the earlier `egypt_construction` rule; `<faction>_goal` scores no VP and refuses its goal action while off). Retired bit positions 3, 22, 25, 31 and 42 stay vacant; old experimental save masks naming those rules load with the retired names ignored. The set is a `Copy` bit mask (`FactionRuleSet`, ordered by declaration, saved as a sorted list of names and absent when empty, so saves, tapes and pins are unchanged). Engine sites read it through the `*_rules` twins of the data functions (`data::building_stats_for_rules`, `unit_stats_for_rules`, `unit_moves_for_rules`, `available_to_player_rules`, `min_city_gap_rules`, `levy_cap_rules`, `terrain_defense_rules`, `ignores_wounds_rules`, `is_hoplite_rules`; `combat::*_rules`; `promotion::level_for_rules`; `goals::switched_off`/`spec_in`) and the `RuleExperiments` methods that wrap them; the old names are the same functions with the set empty. The AI reads the same switched numbers (its building, unit, cost, upkeep, movement and goal-VP lookups go through the view's `rule_experiments`; `Planner::rule_on` gates faction-flavoured valuations), so it never plans around a rule that is off. Where one rule in the table is really two mechanisms the switches are split: the Celts' burning of captured cities and what the sack carries off (`celts_no_keep`, `celts_sack`: with `celts_no_keep` off the Celts keep cities and no sack happens). `sparta_veterans` is the start level, the +50% XP and the sixth level together; `sparta_kill_heal` is the kill heal and the capture heal. `tools/sim/ablate.sh <faction>` runs the paired cloud census and writes `docs/sim-results/faction-ablation/<faction>-<date>/README.md` (win share control against off, the paired difference with its 95% interval, when the rule first applies, and a verdict: pays, dead, backwards or inconclusive).
